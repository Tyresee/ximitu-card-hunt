## 1. 唯一合法顺序

```text
学生点击开始并真人录音
→ 学生说完后结束本次录音
→ 服务端校验 Session / turn / attempt / LearningPack / task / policy version
→ 服务端独立取得 final transcript 和供应商原始评分证据
→ 服务端先判定主知识点是否正确
→ 服务端生成真实得分或无分数的不确定结论
→ 页面先把评价和得分直接展示给学生/教师
→ 有合法得分的回合进入对应骰子档位
→ 骰池随机产生实际骰点
→ 页面显示骰点
→ 棋子按实际骰点逐格移动
→ 真实最终落点结算系统固定 Trigger、地图设施、奖励或剧情效果
→ 处理该落点需要的道具、奖励或玩家选择
→ 保存本回合并轮到下一位
```

任何地图或关卡都不得把顺序改成：

- 先掷骰子、后补分数
- 先移动、后请求评分
- 明确说错后弹教师确认窗
- 用教师按钮代替真人录音
- 用浏览器常量、随机数或模拟对象伪造阿里云分数
- 为某张地图另写一套录音或骰子流程

## 2. 三种评分出口

| 证据结论 | 页面 | 分数 | 骰子与移动 | 掌握证据 |
|---|---|---:|---|---|
| 主知识点明确正确且四项证据完整 | 直接显示评价与加权分 | 真实加权分 | 立即进入对应骰子档位 | 可以记录 |
| 主知识点明确错误 | 直接指出错误并显示低分 | 固定 45 | 立即进入起步骰并移动 | 绝不记录 |
| 证据缺失或确实歧义 | 明确显示未判断/待复核 | `null` | 暂不掷骰、不移动 | 不记录 |

“明确错误”和“证据不确定”是两个完全不同的状态：

```text
明确错误 = accepted scored turn + 45 分 + 继续骰子
证据不确定 = retry / teacher_review + 无分数 + 暂停骰子
```

不得把明确错误送进教师确认窗口。

## 3. 正确答案的固定加权

明确正确时，只使用真实证据：

```text
最终分 =
  知识正确性 × 60%
  + 目标词发音 × 25%
  + 整句发音 × 10%
  + 流利度 × 5%
```

| 分项 | 权重 | 缺失时 |
|---|---:|---|
| 知识正确性 | 60 | 不得出分 |
| 目标词发音 | 25 | 不得出分 |
| 整句发音 | 10 | 不得出分 |
| 流利度 | 5 | 不得出分 |

供应商 `overall` 不能替代主知识点证据，其他高分也不能补齐缺失分项。

## 4. 明确答错的固定处理

例如题目要求 `She has ...`，学生明确说成 `She have ...`：

```json
{
  "result": "accepted",
  "action": "score_low",
  "knowledgeStatus": "wrong",
  "primaryAccepted": false,
  "score": 45,
  "resolution": "knowledge_wrong_low_score"
}
```

必须满足：

- 即使供应商 `overall = 99`，最终仍是 45 分
- 先在页面显示“主知识点用错了，本轮 45 分”
- 不显示“请老师确认学生是否答对”
- 不增加知识掌握星或正确次数
- 增加一次真实发言机会记录并保留错误证据
- 45 分进入起步骰，然后正常随机掷骰、逐格移动和结算落点

## 5. 分数如何进入骰子

当前档位：

| 分数/出口 | 骰子 |
|---|---|
| 80–100 | 传奇骰二选一 |
| 60–79 | 勇气骰 |
| 0–59（包括明确错误 45 分） | 起步骰 |
| 教师确认证据可继续 | 课堂助力骰，无伪造分数 |
| retry / 尚未处理的 teacher_review | 无骰子 |

分数只决定骰子档位，不直接决定实际点数。实际点数必须来自对应的合法随机骰池，
然后再驱动逐格移动。地图效果不能反向修改分数、骰子档位或实际骰点。

### 5.1 可编辑骰面配置的边界

项目所有者可以通过独立、版本化的 `DicePack` 调整六种正式骰子的实体骰面：

- 起步骰、勇气骰、课堂助力骰、稳健骰、冲刺骰、寻宝骰各自必须恰好有六面
- 每面点数只能是 `1–6` 的整数
- 六个实体面始终等概率随机抽取；重复点数等价于该点数占据多个实体面
- 每面至多一种已注册奖励：无奖励、金币、星星、钥匙或卡卡精灵
- 奖励必须是非负且有服务端发布上限，不能携带脚本、表达式或任意效果
- 发布的新版本只供新开的棋局锁定；进行中的棋局继续使用创建时的完整 DicePack 快照

`DicePack` 不得包含或修改：

- `80 / 60 / 0` 分档、明确错误 `45` 分或教师复核边界
- score、transcript、LearningPack、task、地图节点或路线
- 本轮候选骰、指定 `faceIndex`、指定实际点数或重掷命令
- 随机权重字段；概率只能由六个明确实体面透明表达

地图编辑入口可以同时展示“节点布局”和“骰子配置”，但两者必须独立校验、独立保存。
节点布局属于视觉坐标；DicePack 属于 EngineContract/GameRelease 的规则数据，绝不能写进
ThemePack、LearningPack、BoardTemplate 或视觉布局文件。

## 6. 真实性与绑定

正式得分必须同时绑定：

- `gameSessionId`
- `turnId`
- `attemptId`
- `recognitionResultId`
- `learningPackId`
- `learningPackVersion`
- `taskId`
- `AssessmentPolicy` 及结果契约版本
- 允许的服务端评分来源

同一个识别结果只能结算一次。过期、错回合、错任务、错内容版本、伪造来源或缺少真实
证据的结果必须失败关闭，不能退化成“先给一个看起来合理的分数”。

QA 模拟只能验证工程分支，并且必须显式开启；生产默认拒绝。模拟结果不能写成真人录音
或阿里云真实成绩。

## 7. 地图只能从哪里接入

地图允许接入的位置只有：

```text
合法评分
→ 骰子档位
→ 实际骰点
→ 逐格移动
→【地图从这里开始：最终落点效果】
```

地图可以改变落点之后的港口雾笛、信号炮、水门、宝藏、剧情或环境演出，但不得读取
题目、答案、transcript、分数或骰子档位来选择地图效果。

### 7.1 最终落点边界

- 节点自带的奖励、发现、机关、运输、portal、goal、world transition 等属于地图 Trigger；
  只能读取地图、路线、玩家道具、奖励状态和稳定随机输入。
- 题目、答案、真人录音、transcript 与真实评分只属于本回合掷骰前的正式任务。
- 完整逐格移动结束后，只结算真实最终落点的地图 Trigger、道具、奖励或必要选择；不得
  追加课堂题目、第二次录音、第二次评分、第二次骰子或第二段移动。
- `score: null` 没有骰子和移动，因此也没有最终落点结算；明确错误 45 分仍按原流程正常
  掷骰、移动和结算最终落点。
- 旧 `ClassroomEventProgram` 仅作为迁移兼容数据读取，不再进入新 Session 的正式回合链。

## 8. 改动门槛

涉及本流程的任何改动必须同时满足：

1. 用户明确说要改变哪一条行为，而不是从地图/美术需求中推断授权。
2. 解释对真人录音、评分真实性、错误处理、骰子和课堂记录的影响。
3. 同步修改代码、`AGENTS.md`、本文件版本和自动测试。
4. 运行 `npm run verify`。
5. 用线上构建和真人录音完成最终验收；本地模拟不能作为最终成绩证据。
