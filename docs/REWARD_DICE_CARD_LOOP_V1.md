# 奖励—骰子—卡片闭环 v1

- 状态：2026-08-06 用户确认，本地实现与自动化测试已完成，尚未部署
- 范围：通用棋盘运行时、地图编辑器、卡片资源管理与新 Session 配置
- 不在范围：具体题目池内容、地图背景重绘、部署

## 产品边界

唯一课堂主流程保持为：

```text
真人录音
→ 服务端绑定任务并真实评分
→ 页面先显示评价与得分
→ 分数选择合法骰子档位
→ 骰池随机产生实际骰点
→ 棋子逐格移动
→ 真实最终落点结算地图 Trigger、道具、奖励或必要选择
→ 保存并推进回合
```

- 题目和真人语音评分只发生在掷骰前的正式任务中。
- 最终落点之后不再追加课堂题目、第二次录音或第二次评分。
- `score: null` 仍然不产生骰子、移动或落点结算。

## 卡片资源库

- 卡片数量不预设“100 张”之类的业务数量，也不预建空槽位；目录随 owner 新增而增长，服务端仍保留必要的安全容量保护。
- owner 可以新增卡片记录，并上传、预览、替换该卡片的图片。
- 尚未上传图片时必须明确显示“尚未上传”，不得伪造正式卡图。
- 现有西米兔与朋友们的 8 个角色是角色 IP，不等于完整卡片目录。
- 卡片不设置稀有度。
- 每个卡片记录使用稳定 ID；发布后图片引用可更新，但不能靠数组位置识别卡片。

## 奖励与兑换

- 节点奖励只允许：无奖励、金币 ×1、金币 ×2、金币 ×3、卡片盒 ×1。
- 卡片不作为节点直接奖励；每个卡片盒必然开出一张卡片。
- 兑换站显式执行 `5 金币 → 1 卡片盒`；不得继续使用旧的自动
  `3 金币 → 星星 → 钥匙 → 卡片` 链。
- 旧星星、钥匙、精灵奖励必须有显式迁移或兼容读取策略，不能静默丢失用户存档。

## 开盒

- 允许抽到重复卡片。
- 按玩家记录连续重复次数。
- 连续两次抽到重复卡后，下一盒在仍有未收集卡片时必须开出新卡。
- 若卡片库为空，不能消耗卡片盒；若已全部收集，保底退化为普通等概率抽取并明确提示。

## 骰子

| ID | 六个等概率实体面 | 每次掷骰的附加奖励 |
| --- | --- | --- |
| `starter` | 1, 1, 1, 2, 2, 2 | 无 |
| `brave` | 1, 1, 1, 1, 2, 3 | 无 |
| `support` | 1, 2, 3, 3, 4, 4 | 无 |
| `steady` | 2, 2, 3, 3, 3, 4 | 无 |
| `sprint` | 3, 3, 3, 4, 4, 5 | 无 |
| `treasure` | 3, 3, 3, 4, 4, 4 | 金币 ×1、金币 ×2、卡片盒 ×1 中等概率随机一项 |

分数只选择骰子档位，不能指定实际骰面或附加奖励；每次结果必须来自 Session 锁定的
DicePack 与合法随机结算。

## 编辑器与发布

- 地图编辑器保留醒目的入口，并新增“卡片库”页签。
- 卡片图片上传是独立的资源管理动作，不写入 BoardTemplate 或背景图。
- 奖励、骰子、卡片与 Codex JSON 必须使用同一份权威目录。
- 新发布版本只影响新 Session；进行中 Session 继续使用开局锁定快照。
- 旧“节点事件 / ClassroomEventProgram”不再作为落点题目编辑入口；节点事件编辑将迁移为
  地图 Trigger、道具和奖励，不得包含题目、答案、录音或评分字段。

## 验收

1. owner 能新增卡片、上传合法图片、预览并替换；刷新与重新登录后仍存在。
2. 非 owner 无法修改卡片目录或上传正式卡图。
3. 节点奖励只出现已确认的五种合法组合。
4. 兑换站精确执行 5 金币换 1 卡片盒。
5. 开盒允许重复，并能稳定验证“两次连续重复后的下一盒保底新卡”。
6. 六种骰子精确匹配本文件，`treasure` 每次只产生一项合法附加奖励。
7. 页面先显示真实评分，再选骰子、掷骰、逐格移动、结算最终落点。
8. 最终落点后没有课堂题目、录音或评分入口。
9. 桌面与 375px 下卡片上传入口、空状态、错误状态和键盘焦点均清晰可用。
10. 未经当次明确授权不 stage、commit、push 或部署。
