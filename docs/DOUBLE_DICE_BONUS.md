# 双骰机会与三批 UI 优化

日期：2026-11-01（Asia/Shanghai）。用户明确要求三批按顺序全部实施、验证、构建部署，最后交付压缩包；覆盖任务包中的逐批等待和禁止发布要求。

## 规则与所有权

`double_dice` 是一次性地图 bonus。新 v2 布局默认 1–2 个，沿用人数/数量档位、合法节点、间距与区域分布。真正最终落在该格的学生照常领取原格价，服务端记录最多一个待用机会；不新增本次积分倍率或额外钱包事件。全班前进经过或停在该格均不触发双骰。

下次老师奖励该学生时，服务端在同一个原子持久化事务内独立调用两次 `randomInt(6)`、冻结两面并消费机会。浏览器不抽点数。相同 attemptId 先读取已存在回合，再决定是否调用随机数，因此重复请求、丢失响应、重启恢复不会重抽或再次消费。若下一次最终落点再次为双骰格，可获得新机会；全员完圈刷新保留未使用机会。

只有双骰回合增加：

```json
{"dicePolicy":"teacher-double-dice.v1","faceIndices":[2,4],"faceIndex":2,"steps":8,"doubleDiceOf":"original-source-turn"}
```

`faceIndex` 仍对应第一颗。`faceIndices` 长度必须为 2、每项为 0–5 整数，步数严格等于两项加 2。单骰响应不增加这些字段。浏览器仍必须保存机会、已锁骰和已完成移动，再领取服务端冻结的最终落点积分。

双骰仅通过老师路径进入严格 worldPlan 校验，包含 2–12 次正常格移动、全部岔路与零步耗绕圈返回。正好用完点数在 n49 停止；下一步到 n02，经过 n01 的返回演出不再次计圈。语音模式拒绝双骰元数据，包括总和小于 7 的双骰；原评分/骰池/1–6 步边界不变。

## 快照与恢复

新 v2 特效格状态带 `layoutVersion: special-cells.v2` 和 `heldDoubleDiceByStudent`。旧锁定状态不注入字段、类型或新随机池，其完圈刷新继续 v1；旧未锁布局显式重新抽取才使用 v2。旧随机池顺序与抽样保持冻结。

本地机会只有双骰增加两面协议。完成后 runtime 使用 `lastDoubleDice` 校验 `lastDie`；后续单骰删除旧双骰元数据，防止刷新拒绝正常存档。任何坏元数据、保存失败或身份不一致均暂停并保留原事件。

## 展示与性能

课前去除指定标题、说明与积分面板，保留 sr-only 标题及隐藏兼容节点；新开局固定 teacher-led/cloud-harbor，旧存档按原模式恢复。1280×720 的 8 人名单完整可见。

点击后立即出现没有结果的问号骰等待状态；服务器返回后使用原抛出效果。已登记且无待恢复事件时跳过冗余查询，所有未结算回合、请求、bonus 与全班奖励仍保留恢复栅栏。普通跳跃 320ms，镜头并行，正常路径局部更新棋子；云瀑 620ms，返回淡变 110ms；低动态路径保留简化行为。

双骰复用原 `createPhysicalDie`、材质、立方体几何与抛出关键帧。第二颗晚 180ms 落定，随后数字合成 `a + b = n`。单骰原函数和骰子 CSS 均保持 8cb82a5 指纹，不需要更新或放宽原外观锁。持有标记为 🎲🎲，授予演出一分为二飞入学生卡，低动态显示结果并跳过飞行。
