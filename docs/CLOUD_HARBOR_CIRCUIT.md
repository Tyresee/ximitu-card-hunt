# 云港个人绕圈与全班 bonus 刷新

2026-10-28 用户明确要求：当前云港赛道反复绕圈，不再因一位学生到达终点而进入第二空间；全体参与学生完成一圈后，统一刷新 bonus。这一决定覆盖旧“世界只能向前扩展”对新开棋局的限制。

## 当前行为

- 新局组合为 GameRelease 2.4.0 / `route.ximitu-circuit@1.0.0`，只装载原云港四区。Board 2.3.0、World 1.3.0、Level 2.1.0 的节点、道路几何和基础分值保持原版本。
- 每人独立保存 `completedLaps`。到达 `n49` 记一次完圈；若骰点刚好用完，就停在 `n49`，领取这格的原格价。最后一格的下一个耗骰步直接去起点下一格 `n02`；有余步或下次出发时，可保留零步经过 `n01` 的返回演出，离开终点不再次计圈。
- 返回使用明确的 `lap_return` 演出，不创建第二空间、不搬动其他学生、不重置共享地图状态。它不是一条新增的普通道路，不把不存在的道路画进背景。
- 先完成者继续跑下一圈。`lapRound` 表示全班当前尚待共同完成的圈数；全部已登记学生达到该圈数后，服务端只刷新一次。
- 全班前进也遵守同一圈制，可帮助学生过终点。2026-10-31 起，完成挑战并前进后，每位实际移动的学生领取自己新落格的原格价（含触发者）；不连锁触发新的 bonus、运输或挑战。

## 奖励与恢复

跨终点回合先用原 bonus 布局冻结最终落点，完成原回合到账及必要的全班挑战、全班新落格到账，再在服务端事务中增加 `drawNumber`、抽取新布局并清除该布局的消耗标记。老师不能借此在掷骰后任意重抽。

全班推动先由服务端持久化新位置及 `group-final-landing-v1` 的每人奖励事件；浏览器逐格演出结束并保存终态后，调用独立领取接口。原格价来自同局的不可变积分快照，每位学生使用独立稳定的落格 ID，复用签名积分桥与同一家园钱包。部分失败保留已成功回执，其余显示待到账并按原 ID 重试；未全部到账时禁止新骰子及本圈 bonus 刷新。刷新、重连或重复点击不重新移动、不重复发奖。已有历史 confirmed 推动若没有这份奖励事件，不追溯补发。

保留 `bonusAwards`、旧回合、历史布局、已授予的再掷机会及每课全班前进上限；每圈不重置每课上限。新布局使用新的 `sc<drawNumber>-…` 标识，旧请求重试不会重抽、重复计圈或重复发奖。基础格价和已到账钱包不清空、不折算、不补发。

积分规则仍使用平台已锁定的完整 v2 快照，游戏移动策略与金额协议分开。签名落格事件不增加 `lap` 等接口外字段，不修改平台 19321 或钱包账本。

2026-10-31 跨圈恢复修复：原先“到账恢复”和“挑战后续/宝藏演出”并行，演出分支可能先检查完旧布局，随后到账才接纳新布局，造成“新一圈宝藏准备中”锁住掷骰。现在按到账恢复、挑战后续、宝藏演出顺序推进；同局同账号的空闲教师界面发现新布局未展示时，另有去重调度补播，忙碌或挑战结束后再次检查。演出标记可用内存兜底，浏览器存储异常不再造成重复演出或永久锁骰；机会、位置、积分仍须按原规则强制保存。跨圈中请求失败保留原机会和已锁骰子，既不重抽也不重复到账。

## 旧局

没有新圈制标记的旧局继续恢复其精确路线和位置，已锁骰子、已冻结路线及已提交回合不重算；已进入第二图的旧局不自动映射到云港节点。要使用新圈制，重新开局。旧向前远征及 repeatable tail 的规则测试继续保留。

发布保留原游戏版本及源码备份。若已有新圈制棋局，后续回退应优先发布保留圈制读取能力的修复版本；不认识新路线的旧程序不能继续新局。回退不得覆盖权威棋局数据或钱包账本。
