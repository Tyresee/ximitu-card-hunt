# 节点创作交换文件 v1

> 已废止：2026-08-06 起不再生成或导入。旧文件中的 `classroomEvents` 只可用于历史备份，
> 不会迁移为最终落点题目。现行格式见 `NODE_AUTHORING_EXCHANGE_V2.md`。

本文件说明如何用 Codex 批量修改棋盘节点，同时保护正式游戏流程。

## 操作流程

1. 在棋盘页面点击醒目的“编辑地图”，进入编辑器的“Codex JSON”标签。
2. 选择修改焦点，点击“生成交换 JSON”，再点击“复制给 Codex”。交换文件始终包含全部世界和全部节点，焦点只限定本次允许修改的范围。
3. 在 Codex 中用自然语言列出节点 ID 和目标变化，要求只返回完整 JSON，不返回补丁、解释或省略内容。
4. 把 Codex 返回的完整 JSON 粘贴回编辑器，点击“解析并预览”。
5. 逐项检查坐标、奖励和题目事件差异，确认后点击“应用到编辑草稿”。
6. 分别进入“节点布局”“节点奖励”“节点事件”检查结果，再使用各标签顶部的发布按钮。应用交换文件本身不会发布。

推荐给 Codex 的补充指令：

```text
请保持 JSON 的完整结构，只修改我指定范围内 editable=true 的字段。
不要修改 context、resourcePools、base、schemaVersion、contractRef、fixedOutcome、lockReason 或任何规则字段。
返回一份完整、可直接粘贴的 JSON，不要返回 JSON Patch，不要省略未修改节点。
```

## 结构

根对象固定包含：

- `schemaVersion`：交换格式版本，只读。
- `contractRef`：正式游戏链路契约，只读。
- `base`：生成时的发布 revision 和草稿指纹，用于拒绝过期文件，只读。
- `resourcePools`：可选奖励、范围和 LearningPack 事件池，只读。
- `nodes`：按 worldId、nodeId 索引的完整节点对象。

每个节点固定包含：

- `context`：区域、拓扑、条件边、固定 Trigger、关卡绑定及安全结算摘要，只读。
- `placement`：可编辑的视觉坐标。
- `reward`：只有 `editable=true` 时，才能修改资源类型和数量。
- `classroomEvents`：只有对应绑定 `editable=true` 时，才能修改模式或从事件池选择事件。

## 安全边界

- 导入不会修改路线拓扑、岔路、传送、固定 Trigger、评分规则、骰池、骰点、移动规则或进行中的棋局。
- 正式顺序保持为：真人录音 → 服务端绑定任务并真实评分 → 页面先显示评价和得分 → 分数选择骰子档位 → 合法骰池随机产生实际骰点 → 棋子逐格移动 → 最终落点结算地图效果 → 可选课堂事件。
- 预览会拒绝缺失节点、额外节点、未知字段、只读字段变化、越界数值、非法事件引用、超出修改焦点和基于旧草稿/旧发布版本的文件。
- 草稿与发布版本分别管理；发布后的规则只进入新棋局，已经开始的棋局继续使用开局时固定的快照。
- 骰子配置不属于这份交换文件，仍在“骰子配置”标签中独立编辑和发布。
