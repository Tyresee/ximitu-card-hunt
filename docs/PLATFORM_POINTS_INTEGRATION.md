`server/lib/monopoly-landing-points-v1.json`，版本 `monopoly-final-landing-v1`。
它逐项覆盖云港 World 1.2.1 / Board 2.2.1 / Level 2.0.0 的61格，以及远方世界
World 1.0.0 / Board 1.0.0 / Level 1.0.0 的62格。新局保存完整规则快照；节点徽标和
服务端结算使用该快照。草案文件保留原计算依据，不是运行时配置源。

正常骰程只给当前行动的学生 UUID 发放完整路线的最终一格。经过格、运输起点、世界出口、
其他随全班迁移的棋子均不另发积分。旧金币、星星及骰面附加奖已按用户后续决定退役，不折算，不写Growth。
知识答题还没有可供游戏服务查询的正式评分回执，因此本次仅启用默认的老师主持自由记分。

2026-10-31 用户明确要求：全班前进挑战完成后，每位实际移动学生领取新落格的原格价。游戏服务在确认推动时冻结每人的位置、金额和独立 `group-landing:` 落格 ID，浏览器停稳并保存后调用 `POST sessions/:id/group-moves/:instanceId/claim`（只传账号，不传学生、金额或节点）。服务端复用原签名 landing 接口，平台仍从原规则表独立复算金额；无须新增桥协议、改写格价或重启平台。逐人回执支持部分到账和原 ID 恢复，未全部到账前不允许新骰子/完圈刷新。只处理新确认并冻结了奖励的推动，历史已确认无奖励的推动不补发。新落格不连锁触发 bonus、运输或挑战。

### 权威链路

1. 开新局先向游戏服务登记名单，成功后采用服务器生成的世界实例ID与规则快照。
2. 老师发机会并掷骰时，服务端以安全随机数锁定等概率1–6骰面。浏览器不能自报骰点。
3. 浏览器仅提交必要的岔路选择；游戏服务用同版本引擎、持久位置与地图状态重算完整路线、
   运输和跨世界结果。浏览器在保存移动前核对骰子、完整逐格路线及最终格。
4. 本地稳定保存后演出移动；棋子停稳才申请原回合积分。请求不含金额、节点或分数。
5. 游戏服务签名已冻结的事件；19423私有积分桥再次校验登录、学生、版本和格价，
   将奖励、余额、流水、业务去重回执原子写入19321和家园使用的同一账本。

游戏API根为 `/games/monopoly/api/points/v1`：context、sessions登记/查询、roll、
turns/:attemptId/plan、turns/:attemptId/claim、close。桥API与HMAC细节见平台仓库
`docs/MONOPOLY_POINTS_BRIDGE.md`。签名密钥只在两个服务的私有环境文件中，不进入前端。

### 恢复与兼容

浏览器outbox按老师账号隔离，发请求前持久化原幂等键；服务端同局同回合业务唯一。
锁定的骰子刷新后不重抽；已冻结路线恢复原岔路选择；已到账回执不会重发。
服务端只有planned事件时，浏览器不得自动领取：必须本地已提交并显示保存的最终位置。
未到账阻止下一次新骰子，原回合可重试；关闭局不会取消已登记待到账事件。
新旧局不能用同一externalSessionId同时领取整局奖和停格奖。

原存档没有新积分标记时保持旧协议；不借恢复补建即时积分场次，不补发历史局。
原钱包的起始赠送规则、家具价格与存量余额不改。家园打开或刷新时读取同一钱包。

## 权威与确认

目前大富翁的整局状态、骰子和教师机会仍由浏览器运行，不能当作服务端已验证的分数。首版只支持 `teacher_confirmed_session`：新局在平台登记固定学生 UUID 名单和规则快照，教师点击结束整局时确认参与结算。服务端专用 `/monopoly/` 路由固定来源 `ximitu-card-hunt`，浏览器不提交金额、星星、分数或可改写的来源 ID。规则金额、权限、业务唯一性、钱包和流水都归平台服务。

“本章完成”及“继续下一章”不结算平台积分。同一游戏的 `assetGameId` 贯穿章节，只有 `finishCurrentGame` 或结束后明确重试结算会发起完成请求。没有新增二次确认弹窗；有启用规则时原按钮显示“结束本局并结算积分”，并显示锁定金额和教师确认口径。

## 请求与恢复

| 操作 | 接口 | 请求 |
| --- | --- | --- |
| 仅新开整局登记 | `POST /api/game-points/v1/monopoly/sessions` | `expectedUserId, externalSessionId: assetGameId, studentIds` |
| 读取原登记 | `GET /api/game-points/v1/monopoly/sessions/:id` | 无写入 |
| 登记回执丢失恢复 | `GET /api/game-points/v1/monopoly/sessions/by-external/:externalSessionId` | 无写入 |
| 教师确认结束 | `POST /api/game-points/v1/monopoly/sessions/:id/complete` | 仅 `expectedUserId` |
| 读取平台余额 | `GET /api/game-points/v1/students/:id/wallet` | 无写入 |

登记和完成分别保存稳定 `Idempotency-Key`。账号隔离的独立本地记录使用 `ximitu-card-hunt.platform-points.v1:<userId>`；发送写请求前先持久化，失败时不发请求。相同游戏恢复、刷新、重复点击均保留原命令身份。原棋局的保存与结束流程不等待积分网络。

登记失败后只查询原记录：请求已抵达平台则恢复原规则；从未抵达则显示“未登记、未到账”，不能在结局重新创建一局，以免改用后来的规则。旧存档、临时 `seat-*` 身份、缺少 UUID 的旧测试学生不登记、不追溯。未启用规则的已结束局不补发。

结果页显示本局回执、每位学生到账状态及服务端读取的余额；课前页保留最近一局和所有待结算记录。余额读取失败显示“未读取”，不假造零余额。切换账号后不展示或完成旧账号队列；登录过期提供返回平台登录入口，URL 仅携带返回路径。
