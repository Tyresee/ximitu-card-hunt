# 云端开发存储规范

状态：2026-11-11 用户明确要求，后续开发默认遵守。后续用户明确指定的存储位置和更严格的隐私规则优先。

## 默认落点

| 内容 | 默认位置 | 边界 |
|---|---|---|
| 已授权持久化的图片、标准音、视频、模型、导出成品 | 项目已授权的私有 OSS | 沿用环境/租户/项目前缀与鉴权，不自动改公开读 |
| 源码包、安装包、旧发布归档、长期备份 | 私有 OSS | 完成归档须完整回读/SHA-256 校验及恢复索引；不得提前删除唯一副本 |
| 运行代码、当前版、上一版及确实被引用的文件 | ECS 受管目录 | 普通常驻两版；进程/配置引用和无法确认的旧条目继续保护 |
| 数据库、账号、学生存档、积分账本、订单等事务数据 | 原有可靠业务存储 | 不为省盘擅自搬到 OSS，不用对象接口替代事务或文件锁 |
| 上传暂存、构建缓存、日志和诊断 | 有上限的临时目录或轮转存储 | 写清容量、期限和退出清理；不得成为长期备份 |
| 开发工作区、Git 源码、用户指定的本地交付 | 按当前任务保留 | OSS 优先不意味着删除工作区或自动上传个人文档 |
| 禁止留存的原始录音等数据 | 不保存 | 流式或内存处理的旧规则继续有效，OSS 不能成为留存例外 |

新增功能应在设计上传/导出/生成接口时确定 OSS object key、访问控制和元数据，避免先长期落到 ECS 再人工搬运。
现有相对路径、版本哈希清单、离线包和资源加载契约不得直接替换；需要迁移时先适配并验证，保留可恢复旧入口。
使用项目现有 OSS 适配器及服务端凭据，不把密钥写进前端、Git、日志或恢复清单。Bucket、地域、前缀和资源包用量须重新核对，不能从其他项目照抄。

## 发布与失败处理

- 现有三个项目继续使用 `/opt/tim-storage-archive/deploy_artifacts.py`；源码/发布输入和本次备份经私有 OSS 完整回读校验后，才继续相关发布步骤。
- 发布前和成功后执行即时 `finalize`，保留当前、上一版和实际被引用的代码；不能改回“每次创建永久本地备份，等以后再删”。业务历史数据与旧存档兼容不等于永久保存每个 ECS 发行目录。
- 归档不可用时阻止新的持久化发布产物继续堆积。新版本已经健康运行后，收尾归档失败不能触发对健康版本的回滚；下一次发布先补完归档。
- 上传前检查远端空间余量，解包前运行磁盘预检；成功、失败和可处理的中断都清理本次自有暂存。中断残留由受管的有界清理流程处理。原始 Git/数据仍在、且尚未开始依赖该备份的业务变更时，可清理失败的可重建包或临时快照；不得因此删除唯一可恢复数据。
- 小型诊断和恢复索引允许本地保留，但须有明确上限；现有 Pocket Hop 故障诊断只保留一个不超过 8MiB 的槽位。不得把源码包、整盘快照或学生数据塞进该例外。
- 定时维护只做兜底。不得删除、绕过或放宽归档证明、项目锁、进程/配置引用保护、磁盘余量或现有失败/回滚门禁。

## 现有生产边界

学生家园 `/var/lib/pocket-hop/student-homes-v1`、平台 `shared/data`、账号/积分/订单以及独立游戏业务目录，都不是发布垃圾。
不对它们做清理、覆盖恢复、批量改写或无适配迁移。迁移/删除某个既有普通文件之前，先取得完整可恢复副本、验证字节一致并确认没有运行时引用。
原始儿童实时录音继续遵守“不落盘、不上传 OSS”；已授权的标准音和素材成品按原项目接口保存。

## 交付时的检查

只在本次确实新增/改变存储、上传、备份或发布行为时，说明：

1. 哪些内容写到 OSS，哪些必须留本地及其原因。
2. 临时目录、缓存/日志上限、保留期限与失败清理方式。
3. OSS 写入失败时是否会持续产生本地副本；生产存档和当前版是否受保护。
4. 真实上传/完整回读/哈希证明，或明确标注尚未做真实云端验证；不得用 mock 冒充真实 OSS。

纯文案或界面改动无需新增存储流程，也不为验证本规则重启生产服务。
