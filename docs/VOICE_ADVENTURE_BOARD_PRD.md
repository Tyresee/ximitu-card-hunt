## 0. 执行摘要

### 0.1 一句话产品承诺

教师只需在 Codex 中用自然语言说明教材范围、教学目标、课堂时长、人数和偏好玩法，Codex 就能基于游戏平台真实支持的人物、素材、知识点和棋盘能力，生成一份可审核的声控棋关卡草稿，完成教学检查与 1–8 人整局验证，再交由教师在网站中预览、修改、人工发布和启用。

### 0.2 首期核心闭环

```text
教师在 Codex 中描述教学需求
  → Codex 读取平台真实能力
  → 生成结构化关卡草稿
  → 自动校验并模拟全部人数/模式
  → 教师打开审核链接
  → 预览儿童实际体验
  → 人工发布并选择是否启用
  → 课堂开局锁定精确版本
  → 孩子说完整目标句，系统立即自动投骰并展开冒险
  → 教师查看不公开排名的教学证据
```

### 0.3 已冻结的产品决定

1. 首期自然语言入口是 **Codex 对话 + MCP**，不是网页内嵌聊天机器人。
2. 网站只新增两个教师创作主页面：关卡库和 AI 关卡工作台。
3. Codex 只能创建、修改、校验、模拟草稿并提交审核，不能发布、启用或删除正式内容。
4. AI 生成不等于教学正确；人工审核是正式上线前的必要步骤。
5. 正式游戏采用稳定的平面 2D 实现；3D 或伪 3D 只可用于封面与宣传视觉。
6. 语音识别负责转写，句型是否通过由确定性结构与 slot 规则判断，不让大模型在课堂中自由打分。
7. 骰子点数保持真实随机，与音量、语速、发音分和学习掌握度无关。
8. 每张任务必须先满足完整句子结构，再判断主目标与复习目标。
9. 公开竞争只使用位置、道具和冒险收藏；语法掌握度只对教师可见。
10. 课堂开始后锁定关卡版本，后续发布、启用或回退不改变正在进行的课堂。
11. 首期课堂采用同一屏幕、同一麦克风和轮流发言，不承诺多设备联机或自动识别说话人。
12. 标准音在备课或发布阶段预生成并缓存；课堂主循环不依赖实时生成音频。
13. 首发内容必须通过机器可读的 `profile.family-town-have-has.v1` 发布配置档；通用 Schema 的未来能力不等于 v1 可发布范围。
14. 新建关卡时保存不可变的必要需求摘要；草稿修订、校验、模拟和发布产物只追加、不覆盖，确保完整追溯。
15. 儿童的目标句本身就是投骰触发动作；不再要求另说 `Roll the dice!`，也不提供绕过目标句的儿童投骰按钮。

## 1. 产品背景与问题

### 1.1 当前基础

Tim 游戏乐园已经拥有：

- 邀请制教师账号和账号级内容隔离。
- 单词声波防线游戏及稳定的平面 2D 语音交互。
- 阿里云百炼实时 ASR、CosyVoice TTS、图片生成与素材质量检查能力。
- 草稿、发布版本、激活指针、乐观并发和原子存储模式。
- 可扩展的游戏平台首页，目前已有一个真实可玩游戏。

声控奇遇棋不是替换现有单词游戏，而是作为第二款独立游戏加入游戏平台。

当前仓库已经完成声控奇遇棋的产品接口基线、Task Pack Schema 和 MCP 契约，但尚未实现新游戏运行时、独立 Store、Authoring API、MCP 服务、工作台或独立 ASR。本文描述目标产品，不把这些待开发能力表述为现有功能。

### 1.2 教学问题

现有单词游戏擅长让孩子重复输出孤立词汇，但教师还需要一种能够推动孩子主动说完整句子的课堂活动。传统桌游或大富翁可以提高参与感，却通常存在以下问题：

- 教师每次备课都要手工写题、制作卡片和安排难度。
- 游戏得分与教学目标脱节，孩子可能只关注骰子。
- 多人课堂容易出现等待时间长、强者包办、弱者不敢开口。
- 发音识别不稳定时容易把“没听清”误判成“孩子答错”。
- 随机事件和竞争过强时会掩盖学习目的。
- 固定题库难以快速匹配 Power Up 的不同单元和人物。

### 1.3 产品机会

Codex 可以把教师的自然语言教学意图转成受约束的结构化关卡；阿里云可以提供课堂中的语音识别、标准音、原创辅助素材生成和语义质量检查。二者结合后，教师可以把时间放在教学判断和课堂观察上，而不是反复填写表单。

## 2. 产品目标与成功定义

### 2.1 产品目标

- 教师无需编辑 JSON 或理解接口，即可从自然语言获得可审核关卡。
- 每一张任务卡都能明确对应主教学目标、复习目标和完整句型输出。
- 让 1–8 名儿童都获得可验证的发言机会，并支持个人或组队玩法。
- 保留骰子、传送、宝箱、技能和随机路线带来的趣味。
- 让竞争有趣但低压力，不公开比较孩子的英语能力。
- 让 Power Up 人物逐步成为长期熟悉的游戏角色。
- 充分利用现有阿里云能力，同时不把课堂稳定性依赖于实时大模型判断。
- 不破坏现有单词声波防线、素材包和 ASR 行为。

### 2.2 北极星指标

**教师从一段自然语言需求出发，不接触技术结构，成功获得“可审核草稿”的比例。**

首期目标：

- 80% 以上符合模板的需求能一次生成可进入教师审核的草稿。
- 95% 以上草稿能在两轮自然语言修改内消除阻断问题。
- 100% 发布关卡具备当前修订的教学检查和完整人数/模式模拟证明。
- 100% 课堂只读取已发布、已启用且开局锁定的精确版本。
- ASR 会话就绪时间 P95 不超过 3 秒。
- 从儿童目标句结束到骰子动画开始的时间 P95 不超过 2 秒；不含教师人工处理时间。

### 2.3 反向指标

必须同时监控：

- 送审后需要大幅重做的比例。
- 发布后回退或紧急停用的比例。
- 课堂启动失败率和 ASR 中断率。
- 复习目标错误地阻止投骰的次数。
- 1–8 人模拟中发言机会不均的次数。
- 教师通过使用率过高的关卡。
- 孩子平均等待回合和连续等待上限。

不能只优化生成速度而牺牲教学可靠性。

## 3. 用户、角色与任务

### 3.1 核心用户

#### 备课与授课教师

主要任务：

- 快速把本周 Power Up 内容变成可玩的句型任务。
- 根据当天人数切换个人或组队模式。
- 在上课前确认孩子会看到、听到和需要说什么。
- 在课堂中处理没听清、孩子卡住或时间不足。
- 课后判断哪些知识点需要继续复习。

#### 6–10 岁儿童

主要任务：

- 看懂图片和人物关系。
- 在明确提示下说出完整英文句子。
- 说出完整目标句，让系统直接投骰并推动棋子前进。
- 与同伴合作或友好竞争。
- 在失败压力较低的情况下愿意重复开口。

### 3.2 系统角色与权限

| 角色 | 可以做 | 不可以做 |
|---|---|---|
| Codex 创作助手 | 读取平台能力；创建和修改草稿；执行检查与模拟；提交人工审核 | 发布、启用、删除、直接回退正式内容；读取学生录音或个人学习档案 |
| 教师编辑者 | 查看与修改草稿；预览儿童视角；查看问题与建议；送审 | 没有发布权限时不能发布或启用 |
| 发布者/负责人 | 完成编辑者操作；人工确认发布；启用精确版本；从历史版本创建回退草稿 | 不能跳过阻断问题、素材授权或完整模拟 |
| 课堂游戏 | 读取课堂 Session 锁定的发布版本；写入本堂摘要 | 读取草稿、审核中内容或后台创作信息 |
| 儿童玩家 | 在教师已开启的课堂 Session 中参与游戏 | 进入教师后台、查看其他儿童的掌握证据 |

首期权限决定：

- 当前 `owner` 是默认发布者。
- `member` 可以编辑、预览和送审，但首期不能发布或启用。
- 即使编辑者与发布者是同一个人，界面也必须保留独立的“发布确认”动作。

### 3.3 关键用户故事

- 作为教师，我想用一句自然语言说明本周教学目标，让 Codex 自动完成大部分关卡配置。
- 作为教师，我想继续用自然语言修改某几张题，而不是重新生成整套关卡。
- 作为教师，我想在发布前看到儿童实际会经历的正确、错误和没听清场景。
- 作为教师，我想知道 8 人课堂里是否每个孩子都能说到足够次数。
- 作为教师，我想在课堂中随时暂停、跳过动画或人工确认通过。
- 作为儿童，我想通过说出句子获得立刻、清晰且有趣的游戏反馈。
- 作为儿童，我不希望因为系统没听清而被扣分或当众标记失败。
- 作为发布者，我想确认发布的就是刚刚审核的那一版。

## 4. 产品范围

### 4.1 完整产品愿景

声控奇遇棋最终应兼容以下知识点：

- `He / She`
- `is / are`
- `have / has`
- 名词单数与复数
- 可数与不可数名词
- Family
- Family Member
- Family Tree 与家庭关系

同一游戏引擎通过不同 Task Pack 和棋盘模板承载这些知识，不为每个知识点重新开发一套游戏。

### 4.2 v1 垂直切片

首期只做一条可以真实上课的完整链路：

| 维度 | v1 决定 |
|---|---|
| 发布配置档 | `profile.family-town-have-has.v1` |
| 地图 | 家庭小镇 |
| 主目标 | `have / has` |
| 复习目标 | `He / She`、名词单复数、可数名词 |
| 投骰触发 | 普通任务默认“主目标通过或完整句命中触发词”；严格检测任务只接受主目标通过 |
| 语境 | Family、Family Member |
| Boss | Family Tree 视觉场景中的 `have/has` 迁移任务 |
| 任务卡 | 至少 12 张，可按人数与轮次复用不同场景变体 |
| 时长 | Task Pack 认证时长为 12 分钟；课堂可延长到 20 分钟，不可缩短到认证时长以下 |
| 人数 | 1–8 人 |
| 模式 | 1 人个人；2–4 人个人或组队；5–8 人组队 |
| 发言机会 | 每名儿童至少 2 次；1–2 人课堂自动增加变体轮次 |
| 口音 | Power Up 默认英式 `en-GB`，教师可选择美式 |
| 角色 | 首期使用平台占位角色；教师提供并确认授权后替换为教材角色 |
| 视觉实现 | 平面 2D DOM/SVG；封面可采用伪 3D |
| 课堂设备 | 同一教室、同一屏幕、同一麦克风，儿童轮流说话 |

首期示例任务：

- `She has two apples.`
- `He has a blue bag.`
- `She has a brother.`
- `He has three books.`
- Boss：根据简化 Family Tree 说出 `She has a brother.` 等已学结构。

首期 Boss 只把 Family Tree 当作新的观察场景，仍然使用本局已经练习过的 `have/has` 完整句型；`She is Ben's mother.` 等完整家庭关系推理语法留到后续内容包，避免结尾突然考查未教学的新结构。

### 4.3 v1 包含

- Tim 游戏乐园新增声控奇遇棋游戏卡片。
- 家庭小镇棋盘与受控随机事件。
- 1–8 人课堂设置和自动/手动组队。
- 语音任务、完整句结构判断、主目标与复习目标分离。
- 正确目标句或完整句中的受控触发词直接自动投骰，教师拥有转写修正、确认通过和换题后备。
- 关卡库和 AI 关卡工作台。
- Codex MCP 自然语言创作闭环。
- 单题五场景预览与教师确认通过测试。
- 全人数/模式发布认证模拟。
- 人工发布、启用、版本比较和回退草稿。
- 课堂 Session 版本锁定。
- 无公开英语能力排名的课堂摘要。

### 4.4 v1 不包含

- 网页内嵌 Codex 聊天窗口。
- 运行时用大模型自由判断语法。
- 3D 棋盘、物理引擎或自由移动镜头。
- 儿童跨课堂账号、好友、公开排行榜或社交系统。
- 多设备加入、远程联机、说话人识别或多人同时抢答。
- 长期保存原始录音。
- 让 Codex 自定义 JavaScript、棋盘拓扑、骰子概率或任意事件代码。
- 自动抓取或复制未经确认授权的 Power Up 角色图片。
- 一次上线全部语法包；`be` 动词和不可数名词在 v1 引擎稳定后添加。
- 完整 Family Tree 关系图谱、所有关系称谓和多跳关系推理；v1 只使用简化场景复用 `have/has`。

## 5. 教学系统

### 5.1 一题只设一个主目标

每张任务卡有一个 `primaryObjectiveId`，它决定本题的教学掌握证据；另有一个 `rollTrigger`，决定孩子的目标句是否立即推动游戏。两者必须分开，避免“游戏前进了”被误记为“语法已经掌握”。

`rollTrigger` 支持两种受控模式：

- `primary_accepted`：完整句结构和主目标均通过后直接自动投骰。
- `primary_or_keywords`：完整句结构通过后，只要主目标通过，或命中本题配置数量的触发词，就直接自动投骰。

示例任务配置触发词 `has / have`，主目标是 `has`：

| 儿童输出 | 教学结果 | 游戏结果 |
|---|---|---|
| `She has two apples.` | 主目标和复习目标通过 | 立即自动投骰；原因是主目标通过 |
| `She have two apples.` | `has` 主目标错误，不生成掌握证据 | 句子完整且命中 `have`；骰子立即启动，并在结算动画中自然重述正确形式 |
| `He has two apples.` | `has` 正确，`she` 复习项错误 | 骰子立即启动，并在结算动画中自然重述 |
| `She has two apple.` | `has` 正确，复数复习项错误 | 骰子立即启动，并在结算动画中自然重述 |
| `has` | 句子结构不完整 | 即使命中关键词也不投骰；不扣分重试，但消耗一次清晰尝试 |
| `She has` | 缺少任务要求的宾语 | 不投骰；不扣分重试，但消耗一次清晰尝试 |
| ASR 没听清 | 不判断为错误 | 不投骰，免费重试 |
| 教师确认通过 | 只记录参与 | 立即自动投骰，不增加掌握证据 |

若教师希望某张测评题更严格，可选择 `primary_accepted`；此时 `She have two apples.` 进入提示与重试，不会投骰。v1 普通冒险任务默认使用 `primary_or_keywords`，Boss 或明确的检测任务可使用严格模式。

首发配置固定“至少命中 1 个触发词”。触发词不是 Codex 自由填写的任意字符串，只能从平台 Authoring Context 为本题知识点和词汇显式返回的白名单中选择，并同时进入本题 ASR 热词。校验、预览和课堂共用同一归一化器：NFKC、转小写、去边缘标点、折叠空白，只匹配完整 token 或连续 token 短语，按不同配置词计数，不做子串、模糊或近音匹配。

### 5.2 完整句结构优先

判定顺序固定为：

1. 识别语音并生成转写。
2. 判断是否命中一条完整句型结构。
3. 结构完整后分别检查主目标和复习目标，生成真实教学证据。
4. 判断主目标是否通过，或完整句是否命中本题受控触发词。
5. 满足触发规则时，由服务端在同一事务中自动投骰、移动和结算事件。
6. 记录触发原因、提示等级和证据等级。

关键词可以推动游戏，但不能替代完整句子，也不能把错误的主目标改写成掌握证据。

### 5.3 提示阶梯

默认四级提示：

1. 视觉高亮：人物、数量和物品。
2. 句框：`She ___ two apples.`
3. 选择：`has / have`
4. 示范并跟读：`She has two apples.`

规则：

- 没听清不升级提示。
- 系统明确听清但句子不完整，或严格模式下主目标错误时，才消耗一次当前卡的清晰尝试并按规则升级提示。
- 关键词模式下若完整句命中触发词但主目标错误，本回合照常立即投骰，不停下来重说，也不消耗当前卡的重试次数；系统为该儿童和主目标建立一个合并后的待修复项。
- 首次错误冻结待修复项的截止机会，重复错误只增加次数，不能向后延期。最迟在该儿童接下来的第二次个人发言机会中，把原任务或同目标任务以平台固定的“精准挑战”覆盖层呈现：只把触发条件临时收紧为 `primary_accepted`，不修改已发布 Task Pack，并选择下一条实际存在的更强提示；没有更强提示时沿用最高现有提示。
- 待修复状态固定为“待安排 → 已安排 → 挑战中 → 有效通过 / 未通过关闭”。只有儿童实际主目标通过，或教师审计确认“孩子原话正确、仅转写错误”并重判通过，才进入“有效通过”。教师确认通过、技术换题、离席、提前结束或达到清晰尝试上限都进入“未通过关闭”，保留待复习，但不再次自动排队，也不追回星星、移动或收藏。
- 准备进入正常 Boss 时，所有尚未终结且尚未呈现的待修复项统一提前到期；它们至少呈现过一次精准挑战后 Boss 才能开始。若 v1 Boss 个人句与原主目标相同，可直接承担该次挑战。
- 教师可以手动降低或提高提示等级。
- 使用句框、选择或示范后，不计为独立情境证据。
- 每张任务的清晰错误次数受 `maximumClearAttempts` 限制；达到上限后不再自动循环，暂停并让教师选择“示范后跟读并继续”“确认通过”或“换一题”。
- 连续 2 次没听清时不消耗清晰错误次数，但自动暂停并显示麦克风检查、重试、教师确认或换题，不允许无止境自动重录。
- 系统只识别一次目标句，不存在第二条投骰口令；单独说触发词或点击骰子都不能绕过完整句结构。

### 5.4 机会与掌握分开

- **发言机会**：系统是否公平轮到孩子并呈现了任务，可以在课前模拟。
- **有效回答**：课堂中孩子是否结构完整且主目标正确。
- **独立情境**：孩子在图片或迁移任务中，未使用句框、选项、示范或教师通过而完成输出。

发布前只能证明“系统提供了机会”，不能声称孩子已经掌握。

### 5.5 默认教学配比

Codex 在教师没有特别说明时使用：

- 带复习目标的任务占比：30%。
- 迁移任务占比：10%。
- 每名儿童最低发言机会：2 次。
- 至少一次无句框图片输出。
- 至少一次新人物、物品或简化 Family Tree 场景的迁移。
- 同一目标句不得连续出现超过两次。
- 相邻任务尽量更换人物、物品或场景。

### 5.6 知识点兼容方式

| 知识点 | 推荐任务形式 | 主要结构 |
|---|---|---|
| He / She | 看人物说句子、人物替换 | `He/She + ...` |
| is / are | 图片描述、找不同 | `He is... / They are...` |
| have / has | 人物与物品、家庭关系 | `I/They have... / He/She has...` |
| 单复数 | 数量图片、物品收集 | `one apple / two apples` |
| 可数/不可数 | 野餐篮、商店分类 | `some milk / three bananas` |
| Family Member | 角色辨认、身份线索 | `This is my sister.` |
| Family Tree | 后续关系推理内容包、Boss 场景 | v1：`She has a brother.`；后续：`She is Ben's mother.` |

新增知识点只增加目录数据、任务模板和 Task Pack，不修改核心游戏状态机。

## 6. 游戏设计

### 6.1 核心循环

1. 教师创建课堂 Session，选择人数、座位昵称和模式。
2. 当前儿童或队伍获得一张语音任务。
3. 儿童看图并说完整句子。
4. 系统完成结构、教学目标和触发词判断。
5. 主目标通过，或完整句命中本题触发词时，骰子立即自动旋转并产生随机点数。
6. 棋子移动并触发落点事件；若由关键词触发但主目标未通过，同时播放温和的正确重述。
7. 浏览器展示服务端结算；动画完成、跳过或减少动态展示后确认已呈现，下一回合麦克风才打开。
8. 当前回合结算，轮到下一位儿童。
9. 每名仍在场的活动参与者达到最低发言机会，且所有未终结的待修复项至少呈现过一次精准挑战后，进入共同 Boss。
10. Boss 完成后结算冒险收藏、团队星星和教师私有学习摘要。

同一回合的体验阶段固定为 `等待目标句 → 判断中 → 自动投骰与结算动画 → 下一回合`。全程只使用一个目标句语音窗口，不出现额外口令。服务端在返回骰值、移动和事件效果时已经原子提交下一个稳定回合或 Boss，但保持输入门关闭；刷新后可从快照恢复待展示结果并明确展示或跳过，再幂等确认打开下一窗口，不依赖丢失的旧动画回调重新结算。

### 6.2 骰子规则

- 骰子点数为 1–6 的均匀随机结果。
- 目标句 final 只决定是否触发自动投骰，不影响点数。
- 音量、语速、ASR 置信度和发音分均不影响点数。
- 同一回合只能结算一次投骰。
- 骰子结果由服务端权威生成，浏览器动画只展示结果，不能自行决定点数。
- 每个目标句识别结果只能触发一次结算；服务端按“课堂 Session + 回合 + 识别结果或教师动作”幂等处理，重复 final、刷新或重连都不能多走一步。
- 所有回答结算命令在同一事务中保存结算结果和一个逻辑 `answer_resolved` Outbox 事件；允许相同事件 ID 重发，但浏览器只处理一次。
- 服务端提交下一回合后先保持输入门关闭；浏览器确认结算已展示或跳过后才签发下一识别窗口。动画回调丢失时显示“继续下一题”，刷新或重连也必须先同步并确认，服务端不会因超时自行打开麦克风。
- 输入门关闭时保存唯一待展示事件；除匹配事件的展示确认、暂停/恢复，以及显式跳过该展示并提前收尾外，答题、教师通过、换题、重试、修正当前转写等实时命令都被拒绝，不能误结算尚未展示的下一题。
- 儿童不需要也不能单独点击骰子。有识别结果但转写错误时由教师修正；没有识别结果时可重连、确认通过或换题。确认通过会直接触发同一套自动投骰事务。
- 随机种子只用于模拟复现和 QA，不在普通教师界面显示。

### 6.3 人数与组队

家庭小镇首期规则：

| 人数 | 可用模式 | 默认模式 | 棋子 |
|---:|---|---|---:|
| 1 | 个人 | 个人 | 1 |
| 2 | 个人、组队 | 个人 | 1–2 |
| 3 | 个人、组队 | 个人 | 2–3 |
| 4 | 个人、组队 | 两队 | 2–4 |
| 5–8 | 组队 | 两队或四队 | 2–4 |

规则：

- 最多显示 4 枚棋子，避免棋盘拥挤。
- 组队时仍按儿童轮流发言，不能由同一名儿童代替整队。
- 自动组队尽量平衡人数；奇数人数允许一队多一人。
- 教师可以手动调整座位和队伍。
- 座位昵称默认是“玩家1”等，不要求真实姓名。
- Boss 出现前，每名仍在场的活动参与者必须先达到最低发言机会。
- 每个座位状态为“活动中 / 临时跳过 / 已离席”。临时跳过仍保留在最低机会分母中，系统稍后补足；教师确认“已离席”后，该座位退出后续轮转和 Boss 解锁分母，但保留既有学习记录并在结果中标记“未完成本局”。

### 6.4 公平轮转

任务调度独立于棋子位置：

- 棋子位置决定冒险结果，不决定谁有资格发言。
- 发言严格按座位轮转；网络重连后继续原轮次。
- 任何儿童不得连续等待超过一整轮。
- 1–2 人模式自动增加场景变体，避免游戏过短。
- 8 人模式减少非关键动画时长，保证最低输出机会。
- 时间临近结束时，系统优先补足尚未达到最低机会的座位。

### 6.5 竞争与得分

三条互相分离的轨道：

| 轨道 | 谁能看见 | 用途 |
|---|---|---|
| 冒险收藏 | 全班 | 棋子位置、宝箱、徽章和趣味胜负 |
| 知识星星 | 全班共享 | 强调共同完成句型任务 |
| 学习证据 | 仅教师 | 主目标正确、提示等级和迁移表现 |

共同知识星星代表“全班完成了一张任务”，不是掌握分或个人能力分。每张触发并完成投骰结算的任务固定增加 1 颗共享星星；无论触发原因是主目标通过、完整句中的受控关键词、教师修正转写后通过，还是教师确认通过，儿童公开界面的数量都相同。差异只写入教师私有证据。

| 最终判定 | 公开奖励 | 游戏结果 | 教师私有证据 |
|---|---|---|---|
| ASR 没听清 | 暂不变化，不扣分 | 不投骰，免费重试 | `unclear` 次数 |
| 句子不完整 | 暂不变化，不扣分 | 即使含关键词也不投骰 | 尝试、缺失结构、提示等级 |
| 严格模式下主目标错误 | 暂不变化，不扣分 | 不投骰，提示后重试 | 主目标错误和提示等级 |
| 完整句命中触发词，但主目标错误 | 共享星星 +1 | 立即自动投骰；结算动画中正确重述 | `keyword_match` + 主目标错误，不计掌握 |
| 主目标独立正确；复习项可对可错 | 共享星星 +1 | 立即自动投骰 | 有效回答 + 独立情境；复习项单独记录 |
| 使用句框、选择、示范后主目标正确 | 共享星星 +1 | 立即自动投骰 | 有效回答，不计独立情境 |
| 教师只修正错误转写，重判后主目标通过 | 共享星星 +1 | 立即自动投骰 | 有效回答 + `teacher_corrected`；是否独立按修正规则判定 |
| 教师只修正错误转写，重判后仅关键词触发且主目标仍错 | 共享星星 +1 | 立即自动投骰；结算动画中正确重述 | `teacher_corrected` + `keyword_match` + 主目标错误；不计有效回答或掌握 |
| 教师事后修正已经自动结算的转写 | 公开奖励保持原样 | 不再次投骰、移动或触发事件 | 只追加 `evidence_amended`，重算证据及该回答关联的待修复项 |
| 教师确认通过 | 共享星星 +1 | 立即自动投骰 | 只记录参与和 `teacher_pass`，不计掌握 |
| 故障任务被换题 | 中性“绕路”反馈，不扣分 | 进入替代题 | `technical_skip`，不算该儿童错误 |

`voiceEnergy` 只控制任务完成时的共享视觉特效强度，由任务预先配置；它不从音量、发音或答题质量计算，也不改变星星、骰子、移动或掌握证据。个人独立完成徽章首期只出现在教师报告，不在儿童公开界面展示。

禁止：

- 公开显示“谁英语最好/最差”。
- 因 ASR 没听清扣除收藏或星星。
- 抢走其他儿童已经获得的知识星星。
- 用发音分决定前进格数。
- 淘汰落后儿童。

### 6.6 首期棋盘事件

事件来自经过测试的家庭小镇棋盘模板。为了先验证语音、回合和多人公平性，v1 随机事件只启用：

- 小宝箱：获得冒险收藏。
- 固定传送门：移动到预设安全节点。
- AI 奇遇门：本局已达到隐藏句子种子阈值时，从教师课前启用的预审模板中触发一次 20–90 秒屏幕—实体课堂协作；首发模板为“AI 捣蛋精 · 全班修复现实”。

家庭派对 Boss 是达到最低发言机会后触发的固定结尾，不进入随机事件池。友好交换、团队接力和路线选择保留为试点后的模板扩展，待实课证明不会增加等待、状态冲突或儿童挫败后再启用。

AI 奇遇不固定在每轮结束发生。每个已触发骰子的完整句只贡献一枚受限的结构化句子种子；服务端在开局时提交 4–6 枚范围内的隐藏阈值，并同时执行冷却时间与每段触发上限。事件导演只能按当前目标、人数、已确认教具和剩余时间选择预审模板。AI 可生成受限台词、角色分工与美术描述，但不能改写学习证据、骰子、公开分数或奖励规则。

v1 的小宝箱、固定传送门和 AI 奇遇门由 `board.family-town.v1` 固定配置。Codex 可以在已登记模板与材料能力目录中生成结构化内容，但不能编写新事件代码、修改概率或覆盖棋盘状态机。完整策划见 [AI 奇遇门策划](./AI_WONDER_EVENT_CONCEPTS.md)。

### 6.7 教师课堂控制

教师始终可以：

- 暂停或继续。
- 跳过非关键动画。
- 重播标准音。
- 当前回合尚未结算时修正明显错误的 ASR 转写；已经自动结算后使用“修订学习记录”，不改变游戏结果。
- 让孩子免费重试。
- 人工确认通过。
- 跳过故障任务并换一题。
- 进入“提前收尾”或柔和结束本局。

准备进入正常 Boss 时，系统先把所有尚未终结且未呈现的 repair 提前到期；只有所有活动参与者达到最低机会，且这些 repair 至少呈现过一次精准挑战后才解锁 Boss。“提前收尾”可以播放简化 Boss 或结尾动画，但 Session 标记为“提前结束 · 教学覆盖未完成”，未呈现或未通过的 repair 进入“未通过关闭”，不能计作正常完成或满足发布认证。

教师提供句型提示、示范或确认通过不计独立掌握。若原回合尚未结算，教师修正 ASR 转写后可用同一判定器完成该回合的首次结算；若骰子已经启动并推进回合，则使用独立的“修订学习记录”，只更新证据和待修复项，推进证据与 Session 修订以保护并发，但绝不二次投骰或改变当前回合。两种路径都保存修正前后文本、操作者和原因，并把来源记为 `teacher_corrected`；重判后只有主目标通过才生成有效回答证据，仅关键词触发仍保留主目标错误。只有教师明确选择“孩子原话正确，仅转写错误”，且本次没有使用句框、选择或示范时，才可计独立情境，并始终允许教师在报告中单独筛选。

### 6.8 试点后的技能与突发环节

当 v1 真实课堂证明语音、轮转和总时长稳定后，可按同一事件模板逐步开放：

- 指南针：在两条预设路线中选择一条。
- 友谊伞：抵消一次轻微位置后退，不影响知识星星。
- 接力徽章：下一名队友获得一次视觉提示，但仍需自己说完整句子。
- 同伴传送：邀请另一枚棋子一起移动到安全节点。
- 角色交换：两枚棋子交换位置，不交换学习证据。
- 家庭画廊：儿童在线下共同绘画或拼搭，原画立即进入棋盘；视觉理解只提供教师可修正的候选，万相纪念图在后台异步生成。
- 奇遇快递：使用魔术口袋、头箍、闪卡和旋转指针完成受控人物/物品任务。
- 会说话的 Family Tree：在课程终章用实体人物卡、绘画和完整句共同唤醒地图地标。
- 团队庆典：满足全员发言条件后触发共同特效或隐藏路线。

所有技能只影响冒险轨道，不改变主目标判定、骰子概率、最低发言机会或教师私有学习证据。新技能必须先通过多人模拟和真实课堂节奏验证，再进入可供 Codex 选择的能力目录。

## 7. 自然语言关卡创作

### 7.1 首期入口

教师在 Codex 桌面端或 Codex 任务中输入自然语言。Codex 通过 `tim-game-authoring` MCP 连接游戏平台。

首次使用时，关卡库提供“用 Codex 创建”入口和连接状态。入口优先打开 Codex；无法直接唤起时复制一段已经包含平台地址与创作要求的标准提示。v1 由 `owner` 创建和撤销短期 Authoring Token；长期生产阶段再以 OAuth 开放给更多教师角色。日常创作界面不要求教师理解 Token、MCP、Schema 或 JSON。

连接成功后，Codex 只能访问当前教师账号的创作目录与草稿能力。连接失效时保留网站内已有草稿，并引导教师重新连接，不把认证失败表述为关卡丢失。

首期不在网站中再次嵌入聊天模型，原因：

- 避免同时维护两套对话、认证和计费系统。
- 直接复用 Codex 的文件、工具和长任务能力。
- 网站只承担确定性的审核与发布，故障边界更清楚。
- 后续若需要网页内 AI 输入框，可复用同一内容服务和 Schema。

### 7.2 示例提示

> 用 Power Up 本周 Family 内容设计一局 12 分钟家庭小镇关卡。主练 have/has，复习 He/She 和名词复数。4 个孩子分两队，每人至少说两次完整句子。加入一次 Family Tree Boss，使用平台已有角色和占位素材。请生成草稿、完成全部人数模拟并提交审核，不要发布。

### 7.3 Codex 必须完成的动作

1. 读取平台真实支持的棋盘、人物、词汇、知识点、素材和限制。
2. 识别教师的主目标、复习目标、人数、时长和特殊要求。
3. 生成完整 Task Pack，而不是自由文本题目列表。
4. 保存草稿，并在首次创建时写入一份不可变的必要需求摘要。
5. 执行结构、引用和教学校验。
6. 为每张任务设置受控 `rollTrigger`；普通任务选择与目标句有关的关键词，严格检测任务明确关闭关键词触发。
7. 模拟 Task Pack 声明的全部人数和适用组队模式。
8. 修复可自动修复的阻断问题。
9. 提交绑定精确修订的人工审核请求。
10. 返回摘要、提醒、审核链接和醒目的“尚未发布”。

### 7.4 必须追问与默认值

Codex 只追问会实质改变教学结果且无法安全默认的信息。

若确实需要追问，应一次集中提出不超过 3 个简短问题；其余可安全推断的信息使用默认值，并在最终摘要中列明。

必须追问：

- 教师没有指定主目标，且已确认教材映射中也无法唯一确定主目标。
- 教师同时指定两个互相冲突的主目标。
- 指定的人数与模式不受当前棋盘支持。
- 要求使用平台不存在或授权未确认的人物/素材，且占位图不可接受。
- 教材单元名称无法区分且会改变知识点。
- 要求的时长不足以提供每名儿童最低发言机会。

可以直接默认并在摘要中说明：

- 明确要求 v1 家庭小镇但未写主目标：默认主练 `have/has`。
- v1 未写复习目标：默认从权威先修目录选取 `He/She` 和名词单复数；若目录不存在或冲突则追问，不凭空发明。
- 未指定时长：12 分钟。
- 未指定人数：关卡兼容 1–8 人，课堂开局时再选择实际人数。
- 未指定组队：按棋盘的自动模式。
- 未指定口音：Power Up 使用 `en-GB`。
- 未指定复习比例：30%。
- 未指定迁移比例：10%。
- 未指定最低发言机会：每人 2 次。
- 人物图尚未提供：使用明确标记“待替换”的平台占位角色。

### 7.5 自然语言修改

教师可以在同一 Codex 任务中继续说：

- “第三题太难，改成有句框的图片题。”
- “把 Lucy 换成 Ben，但仍然复习 she 的题不要动。”
- “增加两张名词复数复习题。”
- “前三题只要孩子在完整句里说到 has 或 have，就直接摇骰；Boss 必须主目标正确才摇。”
- “Boss 改成两队轮流完成，每个孩子各说一个完整句子。”
- “不要重新生成图片，只调整任务顺序。”

Codex 必须先读取最新草稿，再基于精确修订保存；不能覆盖教师刚刚在网站中完成的修改。发生冲突时，Codex停止写入并说明差异。

如果教师要求 v1 尚未支持的知识点、事件或设备模式，Codex 不得静默写入一个近似实现；它应明确说明当前限制，保持草稿不变，并提供最接近的已支持替代方案。

### 7.6 生成进度与最终摘要

Codex 任务中使用教师可理解的阶段：

1. 正在读取现有角色和教学能力。
2. 正在设计任务卡。
3. 正在检查句型和素材。
4. 正在模拟不同人数。
5. 草稿需要修改，或草稿已提交教师审核。

最终摘要至少包含：

- 草稿名称。
- 主目标、复习目标和迁移任务。
- 普通任务与严格任务的投骰触发方式，以及使用的触发词。
- 任务卡数量。
- 支持人数与模式。
- 预计时长。
- 每名儿童最低发言机会。
- 阻断问题和教学提醒数量。
- 使用的人物与新增占位素材。
- 审核链接。
- “尚未发布”。

Tim 游戏乐园新增第二张游戏卡：

- 主操作：开始游戏。
- 次操作：管理关卡。
- 显示当前启用的关卡名称与版本。

现有单词声波防线卡片和当前素材包行为保持不变。

### 8.2 教师创作页面

只新增两个创作主页面：

1. **关卡库**
2. **AI 关卡工作台**

版本比较、发布确认和回退使用抽屉或弹窗，不增加第三个创作主页面。

### 8.4 关卡库

页面顶部提供“用 Codex 创建”主按钮，并显示“已连接 / 需要连接 / 连接已失效”。教师可以从这里打开 Codex 或复制标准创作提示；技术诊断放在折叠帮助区。

每条关卡显示：

- 关卡名称、地图和教材来源。
- 主目标与复习目标。
- 支持人数和预计时长。
- 已发布版本、当前启用版本和草稿状态。
- 创建来源：Codex、教师或历史版本回退。
- 最后修改人与时间。
- 主操作：继续审核、继续修改、查看版本或开始课堂。

组合状态示例：

- `已发布 v3 · 当前课堂使用`
- `已发布 v3 · 有未发布修改`
- `草稿 · 需要修改`
- `可以发布 · 等待负责人确认`

### 8.5 AI 关卡工作台

从 Codex 审核链接进入时，默认打开“本局总览”，先展示教学目标、支持人数、预计时长、覆盖情况、阻断问题和模拟结论，再由教师下钻到具体任务。

桌面端三栏：

- 左栏：关卡结构、任务卡顺序和 Boss。
- 中栏：当前任务编辑、儿童视角预览，以及教师可理解的“什么时候自动摇骰”设置。
- 右栏：教学覆盖、检查问题、模拟结果和版本信息。

移动端使用分步标签页：

1. 任务。
2. 预览。
3. 检查。
4. 发布。

教师界面不显示 JSON、Schema、UUID、哈希或随机种子；这些只在“技术详情”折叠区出现。

`rollTrigger` 在教师界面呈现为两个选项：

- **完整句中本题主练正确就摇骰**：严格模式。
- **本题主练正确，或完整句至少说中 N 个触发词就摇骰**：列出只能从平台白名单选择的受控触发词，并提示“首发 N=1；只说单词不会触发”。

首期不要求教师逐卡点击机械式“审核通过”。教师可以直接修改任务、查看五种预览，并在整局层面完成一次明确的发布确认。

工作台根据服务端真实状态只提供一个主要下一步：

| 当前状态 | 编辑者/member 主操作 | owner 主操作 |
|---|---|---|
| 新草稿或刚修改 | 检查关卡 | 检查关卡 |
| 有阻断问题 | 修正第一个问题 | 修正第一个问题 |
| 检查通过、模拟缺失或过期 | 模拟全部人数 | 模拟全部人数 |
| 可以发布、尚未送审 | 提交审核 | 提交审核 |
| 等待审核 | 查看审核摘要 / 继续修改 | 审核并发布 |
| 已发布、未启用 | 查看版本 | 设为当前课堂关卡 |
| 已发布且当前使用 | 开始课堂 | 开始课堂 |

任何实质修改都立即回到“新草稿或刚修改”，原检查、模拟和送审状态过期。教师必须按“重新检查 → 重新模拟 → 重新送审”恢复发布资格；owner 接手 member 的审核时看到并批准的是同一精确修订。

### 8.6 教师文案

| 技术含义 | 教师界面 |
|---|---|
| required slot | 本题主练（答对才记有效回答） |
| review slot | 复习提醒 |
| accepted variants | 也可以这样说 |
| blocking issue | 发布前需要处理 |
| warning | 教学建议 |
| stale simulation | 内容已更新，需要重新模拟 |
| revision conflict | 其他人刚刚更新了这份关卡，请先查看变化 |
| unclear ASR | 我没听清，再说一次吧 |
| READY | 可以发布 |
| PUBLISHED | 已发布 |
| active version | 当前课堂使用 |

### 8.7 单题预览

每张任务固定显示五个可执行预览位：

1. 完全正确。
2. 当前模式对应的主目标错误：严格卡预览“不触发”，关键词卡预览“完整句命中触发词后触发但不计有效回答”。
3. 复习目标错误；没有复习项时显示“不适用”。
4. 句子不完整，即使命中触发词也不投骰。
5. 语音没有听清。

跨模式比较是独立的未保存预览，不把另一模式的结果冒充当前任务结果。

另提供独立的“教师确认通过”操作测试。

每次展示：

- 模拟转写。
- 句子结构是否完整。
- 主目标和复习目标分别命中了什么。
- `rollTrigger` 是否命中以及原因是主目标通过还是关键词匹配。
- 儿童看到或听到的反馈。
- 是否立即自动投骰。
- 是否生成掌握证据。
- 教师报告会怎样记录。

在“关键词命中但主目标错误”预览中提供“查看后续精准挑战”。它用正式调度器连续展示：本回合立即投骰、生成的截止机会、后续哪张任务被 `repair_override` 覆盖、实际选中的更强提示，以及儿童主目标通过或未通过关闭后的教师记录。该序列预览不能只显示调度成功标记。

儿童课堂页在每题开始时同时用图标、文字和颜色显示“冒险任务”或“精准挑战”。冒险任务允许完整句中的本题主练或受控触发词推动骰子；精准挑战要求完整句中的本题主练说对。关键词触发但主目标错误时，骰子动画立即开始，正确模型句持续显示到结算结束；播放模型句期间自动压低骰子、移动和事件音效，避免纠正被特效淹没。孩子本回合不需要立即重说，也不需要投骰口令。

### 8.8 整局模拟

教师可手动预览某个人数和模式；发布认证由系统自动覆盖全部声明支持的人数和适用模式。

教师看到：

- 每个配置是否可以正常结束。
- 每名儿童最低实际发言机会。
- 每名儿童在每个目标上的最低呈现机会。
- 最长等待回合。
- 是否出现重复投骰、非法节点或死循环。
- 在关键词错误最不利输入下，`repair_override` 是否能按时呈现、合并去重，并且不让 8 人课堂超出认证时长或阻止正常收尾。
- 哪个人数或模式未通过及如何修正。

发布认证不虚构儿童会不会答对。

### 8.9 发布与启用

发布确认展示：

- 主目标、复习目标与任务数量。
- 支持人数、模式和预计时长。
- 每名儿童最低发言机会。
- 使用的人物、场景、素材及授权状态。
- 当前修订的检查与模拟结果。
- 尚未处理的非阻断提醒。
- 本次与上一版的变化。

教师选择：

- 只发布到关卡库。
- 发布并设为当前课堂关卡。

发布成功但启用失败时，新版本仍保留在关卡库，原课堂版本继续有效。

### 8.10 课堂设置

教师在开局前设置：

- 1–8 个座位。
- 可选昵称；默认玩家1、玩家2。
- 自动或手动组队。
- 课堂时长；可在发布认证时长之上延长，但不能缩短到当前人数与关卡的认证时长以下。
- 是否减少动画。
- 当前发布关卡与版本。

点击开始后创建课堂 Session 并锁定版本。

### 8.11 课堂游戏

课堂界面同时满足：

- 当前儿童、队伍和任务始终清楚。
- 句子主视觉大于棋盘次要信息。
- ASR 转写实时可见但不过度闪烁。
- 正确、主目标错误、复习提醒、没听清使用不同但温和的反馈。
- 目标句尚未完成判断时不显示可操作骰子；触发条件成立后由系统自动播放投骰，不等待儿童再次操作。
- 教师控制常驻但不抢占儿童主操作。
- 8 人模式下仍能快速识别轮到谁。
- 减少动态模式保留清楚的状态变化。

### 8.12 课堂结果

儿童公开看到：

- 冒险路线、收藏和共同知识星星。
- 温和的团队成就。
- 再玩一局。

教师私下看到：

- 每个座位的发言机会。
- 主目标正确、提示后正确和教师通过次数。
- 每个座位 × 主目标的“关键词触发但主目标错误”次数、占该目标完整回答的比例。
- 对应待修复项是否已在后续精准挑战中通过；尚未通过或未完成时明确标为“建议继续复习”。
- ASR 没听清次数。
- 独立图片/迁移情境证据。
- 建议继续复习的目标。
- 本堂使用的精确关卡版本。

不显示公开儿童语法排行榜。

### 8.13 等待、空白与错误状态

| 场景 | 教师看到的行为 |
|---|---|
| Codex 正在生成 | 显示当前真实阶段，不显示虚构百分比；教师可以离开页面 |
| 生成中断但已有草稿 | 显示最后成功保存时间，并提供继续修改或重新交给 Codex |
| 尚无关卡 | 解释“先用一句话创建本周关卡”，提供“用 Codex 创建”和“使用示例关卡” |
| 自动保存中 | 轻量显示“正在保存”；不遮挡编辑 |
| 保存失败或离线 | 保留本地未提交内容，明确提示重试，不能伪装成已保存 |
| 修订冲突 | 显示双方变化并要求选择合并，不静默覆盖 |
| 模拟耗时较长 | 显示正在检查的具体人数与模式，允许离开后返回 |
| 内容更新导致结果过期 | 明确显示“内容已更新，需要重新检查和模拟” |
| 无发布权限 | 保留全部审核能力，明确提示由负责人完成发布 |
| 发布处理中断 | 刷新后从服务端恢复“已发布”或“未发布”的确定状态 |

## 9. 状态模型

产品界面同时呈现三条状态，不用一个标签混合所有事实。

### 9.1 内容准备状态

- 草稿。
- 需要修改。
- 可以发布。

### 9.2 审核与发布状态

- 尚未送审。
- 等待教师审核。
- 已发布。
- 已归档。

### 9.3 课堂使用状态

- 未设为当前关卡。
- 当前课堂关卡。
- 历史版本。

### 9.4 状态规则

- “可以发布”不等于“已发布”。
- “已发布”不等于“当前课堂使用”。
- 修改草稿后，旧检查、模拟和审核立即过期。
- 已发布版本不可原地修改。
- 从历史版本回退时创建新草稿，重新检查、模拟和发布为新版本。
- 页面刷新后恢复真实服务端状态和上一次成功操作。
- 正在进行的课堂不受后续启用或回退影响。

## 10. Codex 与阿里云 AI 的职责

### 10.1 能力分工

| 能力 | 首期提供者 | 用途 |
|---|---|---|
| 自然语言需求理解 | Codex | 理解教师意图、调用平台工具 |
| 结构化关卡生成 | Codex + Task Pack Schema | 生成可检查、可追踪的草稿 |
| 自动修复与送审 | Codex | 修复阻断项并生成审核摘要 |
| 课堂实时转写 | 阿里云百炼 `fun-asr-realtime` | 英语句子转写与热词增强 |
| 标准句音频 | 阿里云 CosyVoice | 备课/发布阶段预生成并缓存任务示范音与提示音 |
| 原创场景/物品素材 | 阿里云图片生成 | 非教材角色的辅助视觉 |
| 图片语义与质量检查 | 阿里云视觉模型 | 检查空白、错义和儿童适宜性 |
| 素材持久化 | 阿里云 OSS | 保存审核后的图片和音频 |
| 句型正确性 | 平台确定性规则 | 完整结构、主目标和复习目标判断 |
| 骰子与棋盘事件 | 平台规则引擎 | 可复现、可测试的游戏状态 |

### 10.2 为什么课堂中不让大模型自由判分

- 延迟和可用性无法保证每一回合稳定。
- 相同回答可能得到不一致结论。
- 教师难以解释“为什么这次不能投骰”。
- 大模型错误不应直接影响儿童竞争结果。
- 确定性 slot 规则更容易测试 Power Up 句型。

阿里云大模型可以在备课阶段提供建议或素材检查，但不得成为课堂主目标通过的唯一裁判。

百炼/Qwen 在首期只可作为非阻断的备课建议，例如发现题目过于重复或句型难度可能不合适；建议必须显示来源并由教师决定是否采用。图片生成、视觉检查和 CosyVoice 生成都发生在备课或发布准备阶段，不占用课堂回合的实时链路。

### 10.3 语音边界

- ASR 不确定时返回“没听清”，不自动判错。
- 只保存结构化课堂结果，默认不保存原始录音。
- 单一目标句窗口的热词来自课堂锁定 Task Pack，并包含本题受控 `triggerTerms`。
- 收到 final 后立即关闭识别窗口并完成教学判断与自动投骰事务；带旧窗口 ID 的迟到结果一律丢弃。
- 回答事务把结算结果和带事件 ID、游标、触发原因、命中词、骰值、移动轨迹及快照的 `answer_resolved` 同时写入事务 Outbox。WebSocket 可用相同事件 ID 至少一次重发，浏览器去重、确认游标并立即播放；丢包、推送前崩溃或断线可补发或通过 Session 快照恢复，不能重复投骰。
- WebSocket 使用明确的 `events_resume(afterEventCursor)` 与 `events_ack(throughEventCursor)` 帧；游标只在单个课堂 Session 内单调有效，未知或过期游标强制 GET 完整快照并从最新游标恢复。投递确认不等于动画/反馈展示确认。
- 普通回答和教师修正、确认通过、换题等所有会结束当前任务的命令都产生同一种逻辑事件；HTTP 响应和 WebSocket 携带同一事件 ID，前端进入同一个去重处理器，避免双播或漏播。
- 下一回合的语音输入门在结算展示确认前保持关闭；动画跳过、减少动态展示、刷新恢复都使用幂等确认，旧动画和音效不能进入下一语音窗口。
- 播放 TTS、提示音或关键词错误重述时保持麦克风关闭，标准音不能回灌成新的回答。
- 已经产生识别结果但转写错误时，允许教师修正并保留前后文本与原因：未结算回答可重判并首次结算，已结算回答只能修订学习证据和待修复项，不能二次投骰。连接失败或没有识别结果时，只允许重连、教师确认通过或换题，不能把不存在的结果伪装成“修正转写”。
- 课堂没有独立投骰口令或儿童点击骰子的后备；教师确认通过会直接触发自动投骰，但只记录参与、不记录独立掌握。
- 首期 ASR 只支持同一教室、同一设备、按座位轮流发言；不尝试自动区分多个同时说话的儿童。
- 旧单词游戏 `/ws/asr` 保持不变；声控棋使用独立会话路径。

### 10.4 与现有游戏平台的兼容边界

- 声控奇遇棋采用独立路由、内容 Store、激活指针、课堂 Session 和 ASR 会话路径。
- 不复用或改变现有单词游戏的 `activePackId`、单词内容结构或 `/ws/asr` 行为。
- WebSocket 升级入口需要统一分发到旧游戏和声控棋处理器，旧连接必须继续通过回归测试。
- 两类语音连接进入统一的账号会话连接注册表；退出登录、改密、重置密码、账号停用、撤销会话或服务关闭时，必须同时终止旧游戏和声控棋连接。
- 首期继续使用单 Node 进程与原子 JSON 存储模式。每个 Session JSON 同时包含课堂状态、首次命令结果、单调事件序号和不可变 Outbox；一次命令用租户串行队列、事务日志、临时文件 `fsync`、原子 rename 和目录 `fsync` 整体提交，启动恢复不能暴露“状态与事件只写了一半”。
- 如果改为多进程或多实例部署，必须先把上述同一原子边界迁移到支持跨进程事务的一致性存储。

## 11. 内容与人物策略

### 11.1 Power Up 人物

- 首期使用平台占位人物完成产品和工程验证。
- 教师后续提供人物图片、名称、代词和家庭关系。
- 平台为每个人物建立稳定目录 ID。
- Codex 只能引用平台已存在的人物 ID，不能凭空创建教材角色。
- 授权状态由教师在服务端目录确认，Codex 无权把素材标成已授权。
- 替换占位图不改变已有 Task Pack 的人物语义引用。

### 11.2 原创辅助素材

可由阿里云生成：

- 家庭小镇背景。
- 苹果、书包、牛奶等物品。
- 宝箱、指南针、传送门和徽章。
- 非教材专属的通用 UI 插画。

所有生成图片必须通过结构质量、语义匹配和教师审核后才能发布。

### 11.3 教材映射

每个关卡记录：

- 教材名称。
- 级别、单元和课次。
- 教师参考说明。
- 使用的知识点目录 ID。
- 使用的人物、词汇和素材目录 ID。

Codex 不能虚构教材单元；平台没有数据时，草稿明确显示“待教师确认”。

## 12. 异常与恢复

| 场景 | 产品行为 |
|---|---|
| 自然语言信息不足 | 只追问会改变结果的必要信息；可安全默认时使用默认并写入摘要 |
| Codex 生成中断 | 不产生正式内容；已保存草稿保留，可继续生成 |
| 保存超时 | 重试不生成重复草稿；恢复后显示上次是否已保存 |
| 教学检查失败 | 草稿保留；错误定位到具体任务并给出可理解建议 |
| 多人模拟失败 | 阻止送审或发布；显示失败人数、模式和原因 |
| 人物或素材缺失 | 使用明确占位或阻止发布，不静默替换 |
| 素材授权未确认 | 可继续编辑和预览，不能发布 |
| Codex 与教师并发修改 | 不覆盖教师版本；要求查看差异后重新合并 |
| 送审后再次编辑 | 原审核失效，回到草稿 |
| 发布处理中断 | 刷新后能确定已发布或未发布，不停在未知状态 |
| 重复点击发布 | 只产生一个正式版本 |
| 发布成功、启用失败 | 新版本保留；旧启用版本继续可用 |
| 新版本课堂加载失败 | 不破坏上一有效课堂版本，可继续使用旧版 |
| ASR 连接失败且没有识别结果 | 游戏不开始计时；提示检查麦克风并允许重连，也可由教师审计后确认通过或换题；不显示“修正转写” |
| ASR 已有结果但转写错误 | 教师可修正转写；保存原文、修正文和原因后调用同一判定器 |
| ASR 没听清 | 免费重试，不升级错误记录 |
| TTS 失败 | 显示文本并允许教师示范，不阻断课堂 |
| 玩家临时离开 | 教师可跳过本轮；其最低机会仍在后续补足 |
| 课堂中发布或回退 | 当前课堂不变，下次开课才采用新版本 |
| 权限不足 | 说明需要发布者操作，不泄露其他账号内容 |

## 13. 儿童安全、隐私与无障碍

### 13.1 儿童体验

- 不使用羞辱、刺耳失败音或“你说错了”等文案。
- 不因系统没听清扣除奖励。
- 复习目标错误使用自然重述，不阻止主循环。
- 教师通过不会公开标记该儿童需要帮助。
- 随机事件最多造成轻微位置变化，不剥夺已获得的学习成果。

### 13.2 数据与隐私

- 不要求儿童账号或真实姓名。
- 座位昵称可以只存在于课堂 Session。
- 原始麦克风音频只在会话期间流式传输，默认不落盘、不写 OSS。
- 课堂摘要使用座位 ID，不暴露给 Codex。
- Codex 不能读取学生录音、身份资料或个人学习档案。
- 日志不记录完整 Codex 对话，只保留必要需求摘要和版本来源。

### 13.3 无障碍与设备

- 支持鼠标、触控和键盘。
- 语音识别异常时，教师可用鼠标、触控或键盘操作：已有结果可修正转写，没有结果可重连、确认通过或换题；不向儿童提供绕过目标句的投骰按钮。
- 颜色不是唯一状态提示。
- 支持 `prefers-reduced-motion`。
- 关键文本达到可读对比度。
- 目标视口：1440×900、1024×768、390×844。
- 手机端可审核关卡，但正式 5–8 人课堂建议使用平板或桌面屏幕。

## 15. MVP 验收标准

### 15.1 自然语言创作

1. 教师无需编辑 JSON，即可从一段中文自然语言需求生成结构化草稿。
2. Codex 生成前会读取平台真实人物、知识点、素材和棋盘能力。
3. Codex 不能引用不存在或当前账号无权使用的资源。
4. 信息不足时只追问必要问题；使用默认值时在摘要中明确说明。
5. 同一 Codex 任务可以用自然语言修改局部任务，不重新生成未要求变化的内容。
6. Codex 完成后返回可用审核链接，并明确“尚未发布”。
7. 任何 Codex 工具路径都无法发布、启用或删除正式内容。

### 15.2 教学判定

8. 在配置 `has / have` 触发词的普通任务中，`She have two apples` 被记录为 `has` 主目标错误，但因完整句命中 `have` 而直接自动投骰，且不生成掌握证据；严格任务则不投骰。
9. `He has two apples` 在主目标为 `has` 时立即自动投骰，并自然纠正代词复习项。
10. `She has two apple` 在主目标为 `has` 时立即自动投骰，并自然纠正复数复习项。
11. 只说 `has` 或 `She has` 返回句子不完整，即使命中触发词也不投骰。
12. ASR 没听清不记为儿童错误。
13. 教师确认通过直接自动投骰，但不增加掌握证据。
14. 使用句框、选择或示范后不计独立情境。
15. 课堂正确性使用确定性规则，断开大模型仍能完成已加载关卡。

### 15.3 多人与玩法

16. 1–8 人均能创建有效课堂 Session。
17. 5–8 人自动进入受支持的组队模式，棋盘最多 4 枚棋子。
18. 每名儿童在 Boss 前至少获得配置的最低发言机会。
19. 相同版本和随机种子的模拟结果可复现。
20. 骰子点数不受音量、语速、置信度或发音分影响。
21. 骰子由服务端生成；同一个目标句 final 或教师动作在刷新、重连或重复事件后仍只能投骰并结算一次。
22. 正确目标句或完整句中的配置触发词会直接自动投骰，界面不会要求儿童另说 `Roll the dice!`，也没有可绕过目标句的儿童投骰按钮。
23. 随机事件不会扣除已获得的知识星星或淘汰儿童。
24. 8 人模式下最长等待和总时长通过发布认证门槛。
25. v1 随机事件池只有小宝箱和固定传送门；Boss 按教学进度固定触发，不依赖随机落点。

### 15.4 教师审核与版本

26. 教师能从儿童视角预览正确、当前模式对应的主目标错误、复习目标错误、句子不完整和没听清；不适用场景明确显示，不伪造输入。
27. 教师能独立测试“确认通过”操作。
28. 每个阻断问题定位到具体任务，并说明如何处理。
29. 草稿修改后，旧检查、模拟和审核立即过期。
30. 只有 `owner` 可以完成首期发布和启用。
31. 发布请求绑定人工审核的精确草稿、内容哈希、检查和模拟结果。
32. 发布与启用是两个独立、状态清楚的操作。
33. 重复发布只产生一个版本。
34. 回退从历史版本创建新草稿，不覆盖历史。
35. 关卡库能显示“已发布 v3 · 有未发布修改”。
36. “用 Codex 创建”入口能显示连接状态；连接失效不会删除或覆盖网站内已保存草稿。
37. 草稿保存超时后使用同一请求重试，只产生一个草稿修订，并能从服务端确认第一次请求的最终结果。
38. Codex 与教师并发修改时不会覆盖教师的新修订；界面能显示差异并要求重新合并。
39. 发布请求中断后刷新页面，能恢复为确定的“已发布”或“未发布”，不会产生未知或重复版本。
40. 发布成功但启用失败时，新发布版本保留，原当前课堂版本继续有效。

### 15.5 课堂稳定性

41. 游戏只读取已经发布并启用的精确版本。
42. 开局后刷新、重连、发布新版本或回退都不会改变本堂内容。
43. ASR、TTS 或网络异常均有明确、可恢复的课堂行为。
44. 原始录音默认不持久化。
45. 不同账号不能互相读取或修改关卡。
46. 声控棋的 ASR、激活指针和内容库不改变现有单词声波防线。
47. ASR 会话就绪 P95 不超过 3 秒；儿童目标句结束到骰子动画开始 P95 不超过 2 秒。
48. 发布前至少真实走通 1 人、4 人和 8 人三种课堂流程，并记录等待、重连与教师后备操作。
49. `npm run verify`、`npm run smoke` 和旧 `/ws/asr` 回归测试全部通过。

### 15.6 页面质量

50. 教师无需查看 JSON、哈希或技术 ID 即可完成审核和发布。
51. 1440×900、1024×768 和 390×844 无横向滚动或关键操作遮挡。
52. 键盘和触控均可完成关键流程。
53. 减少动态模式仍能清楚表达投骰、移动和事件结果。

### 15.7 权限与追溯

54. 任意发布版本都能追溯到必要需求摘要、草稿修订、检查、模拟、送审、发布和启用记录。
55. 任意课堂摘要都能追溯到开局锁定的精确发布版本。
56. 版本历史能区分 Codex 生成、Codex 修改、教师修改和历史回退。
57. Codex Authoring 权限无法读取学生录音、身份资料或个人学习档案。

### 15.8 运行状态机与会话安全

58. 每回合只经历一个目标句识别窗口；final 触发服务端判断与可能的自动投骰，旧窗口迟到结果、TTS 回灌和背景声音不能触发第二次结算。
59. 课堂不能以低于 Task Pack 发布认证时长的设置开局；Phase 0 必须用真实同屏单麦流程验证 8 人、12 分钟、每人至少 2 次发言是否可达。
60. 退出登录、改密、密码重置、账号停用、会话撤销和服务关闭都会终止该账号的旧 `/ws/asr` 与新声控棋 ASR 连接。

### 15.9 教师流程与课堂终态

61. 教师修改已送审草稿后，工作台明确回到“检查关卡”，并只能按重新检查、重新模拟、重新送审恢复发布资格；owner 无法发布 member 修改前的旧审核修订。
62. 临时跳过的座位仍需补足机会；永久离席座位退出后续轮转与 Boss 分母并在结果中标记未完成；提前收尾不能伪装成正常 Boss 完成。
63. 独立答对、提示后答对、完整句关键词触发、教师修正转写后触发和教师确认通过在儿童公开界面都固定增加 1 颗共享星星；修正后主目标通过与仅关键词触发的证据分开，差异仅进入教师私有报告。
64. 达到清晰错误上限或连续 2 次没听清时，任务进入可由教师处理的暂停状态；儿童不能通过单说关键词或点击骰子绕过完整句结构。
65. 缺少主目标时遵循“教师明确指定 > 唯一教材映射 > v1 `have/has` 默认 > 追问”，复习项只能来自教师指定或权威先修目录。
66. v1 的小宝箱和固定传送门由家庭小镇模板固定，Codex 无法开关事件或修改概率。
67. 教师修正 ASR 转写会保留修正前后内容并重新判定；只有“孩子原话正确、仅转写错误且未使用提示”才能保留独立情境证据。
68. Session 创建会冻结人数、模式、座位顺序、稳定座位/队伍 ID、认证时长和精确关卡版本；回答判断与自动投骰在一个命令中结算，教师通过、换题、离席与提前结束也通过携带命令 ID、状态版本和回合 ID 的统一服务端命令契约恢复与去重。
69. `profile.family-town-have-has.v1` 以机器规则阻止非 12 分钟、少于 12 题、非 1–8 人全覆盖、关键词模式命中门槛不等于 1、主目标超出 `have/has`，或包含 `be`、不可数名词、完整 Family Tree 关系的草稿进入 `READY`。
70. 新建关卡必须提交 1–1000 字的必要需求摘要；后续 Codex 或教师修改不能覆盖它，任意发布版本都保存摘要及其哈希。
71. 每次草稿保存都产生不可变修订快照；fast/full 校验、模拟和规则引擎重跑都使用唯一产物 ID 追加保存，不覆盖相同修订的旧产物。
72. 每张任务必须声明 `rollTrigger`；关键词必须来自 Authoring Context 为本题引用知识点或词汇提供的白名单并进入 ASR 热词，完整句要求不可关闭。
73. 每张卡的五个预览位能证明主目标正确自动投骰、当前模式对应的主目标错误行为、复习目标错误、结构不完整不投骰和 ASR 没听清不投骰；跨模式比较不冒充当前卡结果。
74. 校验、预览和课堂运行共用同一触发词归一化器；只匹配完整 token/短语并按不同配置词计数，`he` 不命中 `she`，`have` 不命中 `behave`。
75. `keyword_match + primary_error` 不阻塞当前投骰，但会为同一儿童和目标合并建立待修复项并冻结首次截止机会；准备进入普通 Boss 时，所有未终结且未呈现的 repair 统一提前到期并至少呈现一次“精准挑战”。
76. 儿童能预先看见“冒险任务 / 精准挑战”；关键词错误的正确模型句持续显示，TTS 播放时游戏音效自动压低。
77. 只有存在识别结果时才能修正转写；没有识别结果时使用重连、教师确认通过或换题。
78. 回答结算与唯一逻辑 `answer_resolved` 在同一事务 Outbox 中持久化；相同事件 ID 可至少一次重发，重复、丢失、推送前崩溃、刷新或重连都不会产生第二次结算。
79. 自动回答和教师修正、确认通过、换题等结束任务的命令都生成同一种逻辑事件；HTTP 与 WebSocket 的相同事件 ID 进入一个去重处理器，不双播也不漏播。
80. 下一回合或当前回合重试只有在结算/反馈展示幂等确认后才激活新的语音窗口；动画故障、跳过、减少动态、刷新或重连期间不会误收下一回答。
81. 未结算回答的转写修正可以首次结算；已结算回答只能追加证据修订并调整相关待修复项，同时推进证据与 Session 修订但保持当前回合及游戏效果不变，绝不再次发星、投骰、移动或触发事件。
82. 待修复状态严格按“待安排 → 已安排 → 挑战中 → 有效通过 / 未通过关闭”终结；重复错误不延期，教师通过、技术换题、离席、提前结束或尝试耗尽都不能伪造修复通过。
83. 教师能执行“关键词错误 → 后续精准挑战”的序列预览，看到实际覆盖任务、实际提示选择和两个修复终态；提示缺级时确定性选择下一条现有更强提示，否则沿用最高提示。
84. 输入门关闭时只允许匹配事件的展示确认、暂停/恢复和显式跳过展示后提前收尾；其他答题或教师结算命令返回 `PRESENTATION_PENDING`，不能作用于下一题。
85. WebSocket 的 `events_resume`、`events_ack`、游标单调/断档规则和完整快照恢复均可测试；所有事件型 HTTP 响应返回同一 `eventId + eventCursor`。
86. 首期 Session JSON 在一次 WAL + `fsync` + 原子 rename mutation 中同时保存状态、首次命令结果、事件序号和 Outbox；任一崩溃边界恢复后都不存在半提交结算。

## 16. 版本实施计划

### Phase 0：产品与交互冻结

- 完成本 PRD。
- 绘制关卡库、AI 工作台、课堂设置、游戏和结果页低保真流程。
- 用一个完整 have/has Task Pack 验证所有页面信息。
- 先做阿里云实时 ASR 延迟、长连接恢复和同设备轮流发言技术验证。
- 确认旧 `/ws/asr` 与新声控棋会话可以由同一服务稳定分发且互不影响。

完成门槛：教师可以只看原型讲清从自然语言到开课的完整过程；ASR 与双游戏 WebSocket 技术验证没有阻断项。

### Phase 1：内容内核

- Task Pack Schema 与目录。
- 共享内容领域服务，以及独立关卡 Store、修订、幂等、审计、发布版本和课堂锁定。
- 完整句结构与 slot 判定器。
- 家庭小镇棋盘模板和确定性模拟器。

完成门槛：不用 Codex，也能加载一份人工编写的关卡完成 1–8 人规则模拟。

### Phase 2：可玩垂直切片

- 家庭小镇 2D 棋盘。
- 回合、任务、提示、服务端权威投骰、移动、小宝箱、固定传送门和脚本化 Boss。
- 阿里云 ASR、预生成并缓存的 CosyVoice 标准音与课堂控制。
- 课堂设置和结果摘要。

完成门槛：使用固定 have/has 关卡完成一节真实试讲。

### Phase 3：教师工作台

- 关卡库。
- 三栏工作台。
- 单题预览。
- 整局模拟。
- 版本比较、发布、启用和回退。
- 基于共享内容服务的浏览器 REST、Cookie + CSRF、同源校验和确定性失败恢复。

完成门槛：非技术教师不查看 JSON 即可审核并发布人工关卡。

### Phase 4：Codex 自然语言创作

- `owner` 创建和撤销的短期 Authoring Token。
- MCP 五个工具和 Bearer 适配；复用 Phase 1/3 的共享内容服务，不复制一套内容逻辑。
- Power Up 教学设计技能。
- 草稿生成、自动修复、审核链接和自然语言修改。

完成门槛：教师只通过 Codex 自然语言完成从需求到送审。

OAuth 与更多教师角色的 Codex 连接在首期 PAT 流程稳定后加入，不阻塞单 `owner` 试点。

### Phase 5：课堂试点与扩展

- 1、2、4、6、8 人分批试课，其中 1、4、8 人是发布前必测配置。
- 观察等待时间、提示使用、教师通过和 ASR 没听清率。
- 修正教学配比与动画节奏。
- 增加 `is/are`、不可数名词和完整 Family Tree 内容包。

完成门槛：至少三种人数配置真实课堂稳定完成，且没有 P0/P1 教学或运行问题。
