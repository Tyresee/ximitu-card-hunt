## 目标

学生资料库用于跨课堂保留稳定学生身份和个人资产。开局次序固定为：

```text
从资料库选择本节课学生
→ 按选择顺序分配唯一角色
→ 锁定本局学生 UUID 和资产快照
→ 开始正式语音评分与棋盘回合
```

资料库不得读取或改写题目、录音、转写、得分、骰子档位、骰点或地图规则。

## 课前加载（2026-09-23）

登录身份确认后立即请求学生资料，与地图布局、骰面和节点奖励配置并行。配置尚未返回时
允许选择学生和角色；“出发寻宝”以及新局创建函数仍等待初始化结束，避免提前锁入默认
配置。资料继续从认证接口实时读取，不增加跨账号的本地名单缓存。

修复前一次线上网络记录：学生请求在页面约 8.04 秒时才发出；前一批布局、骰面和奖励
接口耗时约 4.83–4.87 秒，学生请求自身耗时 2.30 秒。该记录是本次采样，不是固定性能
保证。本地将配置接口人为延迟 25 秒后，8 名虚拟学生已先显示且可选角，开局按钮仍显示
“正在准备棋盘…”。行为回归覆盖慢配置、认证失败和开局期间的快照保护。

并行请求上线后，学生请求起点在同次 Chrome 对比中提前到约 3.20 秒，但静态美术仍会
重复完整下载并占用连接。游戏服务补充 ETag/304 内容校验以复用未变化的图片、模块和
样式；学生资料接口保留 `no-store`，不以过期名单替代最新数据。

## 身份与租户

2026-10-28 课前名单与角色：增删学生时按学生 UUID 保留仍在名单内的角色，不能清空整份角色数组或把角色按移位后的序号分给别人。新增学生显示“待选角色”，移除学生释放其角色；新建学生的回执到达时，采用当时最新的名单。恢复棋局后返回设置，按存档座位顺序对应角色；首次资料加载完成前保留这份对应，加载成功后才剔除真正缺失的学生。此规则只调整课前选择，不改写进行中或已恢复棋局锁定的角色、学生身份和资产。

- 每个学生使用服务端生成的稳定 UUID，不使用姓名或座位序号作为资产主键。
- 每份资料保留正式姓名，并可记录游戏昵称、课程阶段和教学备注。游戏界面优先显示昵称；未设置时回退为正式姓名。
- 资料库归属项目主账号；同一项目的受邀老师共享这个资料库。
- 新棋局支持 1—8 位已选学生，角色必须全部分配后才能开始。
- 旧本地棋局的 `seat-*` 身份仍可恢复，但不得冒充某个学生写入资料库。

## 资产口径

每个学生保存：

- 当前金币余额、历史获得金币、历史消耗金币；
- 卡片总张数、不重复卡片数、重复卡片数及按卡片 ID 的数量；
- 老师确认但尚未提供具体卡片 ID 的历史卡片数；该数计入卡片总数，但不冒充某张具体
  卡片，也不参与重复卡与新卡保底判断；
- 玩家资产核心账户快照、有界的结算 ID 去重集合和有界的资产历史。

当前正式资产只有金币和卡片。5 枚金币只能在最终落到兑换站后，由玩家主动兑换 1 张
随机卡片；地图和骰子也可直接发卡片。旧卡片盒字段只允许兼容读取，不得展示、累计或
写入新结算。

## 写入与恢复

- 浏览器不能直接将任意余额覆盖服务端；服务端必须从有界的金币奖励、兑换和卡片奖励事件独立复算账户结果。
- 每次写入携带学生资料 `revision`，并发修改必须显式冲突，不得静默覆盖。
- 首页只承担快速建档和本节课选人；正式姓名、游戏昵称、课程阶段和教学备注通过独立资料管理窗口编辑。
- 资料管理窗口只读展示金币和卡片，不能绕过游戏结算手工改数。
- 每次结算使用唯一 `settlementId`；重放同一 ID 必须返回幂等结果，不重复加资产。
- 本地 Session 保存待同步结算队列。网络中断时保留已接受回合，恢复后按原结算 ID 自动重试。
- 资料库文件用私有权限和临时文件原子替换保存；损坏时必须失败关闭，不得当作空资料库覆盖。

## 不可破坏的主循环

学生资产只在骰子完成合法随机、棋子完成逐格移动、最终落点完成结算后写入。不得为了个人资产而跳过或重排真人录音、服务端评分、先显示得分、骰子、逐格移动和最终落点的顺序。

## 最低验证

- 存储单测：建档、重名、持久化、资产复算、伪造余额、版本冲突、幂等重放。
- HTTP 测试：认证、建档、列表、结算与重放。
- 前端契约：课前选人、稳定 UUID、资产初始化、开局门禁、本地待同步队列。
- 真实浏览器：桌面端、手机端、建档、选人、角色分配与刷新重载。
